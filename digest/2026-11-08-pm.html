深度閱讀

1. EDGAR：用「人造的失敗」訓練一步 diffusion，來修 Gaussian 頭像

arXiv:2611.07909｜cs.GR｜KAIST Visual Media Lab

問題：從單眼影片或幾張照片建的 Gaussian head avatar 本來就欠約束，常見模糊、貼圖拉伸、飄浮的頭髮和時間上的抖動。直接拿 SDEdit 類的 diffusion 去修，模型不知道這個人原本長什麼樣，容易改掉身分、每格修得不一樣。更根本的問題是：沒有「壞掉的 avatar 渲染 vs. 正確影像」的成對資料。

方法：作者先造資料集 EDGAR-SET。每筆是三元組：劣化渲染、ground truth、同一人的參考圖。真實部分用 NeRSemble 的 99 個人、以 RGBAvatar 在 1 到 4 個視角下故意訓練不足；合成部分用 CAFCA 的 1,500 個人、以原版 3DGS 建模。劣化靠改變訓練條件（例如輸入視角數）自然產生，涵蓋飄浮 Gaussian、過度平滑、幾何錯位與視角不一致，再用 LPIPS 篩掉約一半和無法挽救的樣本，總共約 40 萬張高解析圖。模型以一步的 SD-Turbo 為骨幹，凍結 residual block 和 cross-attention，只訓練 self-attention；參考圖用 Sapiens 特徵經 cross-attention 注入，配 zero-init 卷積，所以初始時等同 SD-Turbo；另外加一個六個 expert 的 MoE router。Loss 是 L2 + LPIPS + VGG Gram，加上 POSTER V2 特徵的表情 loss（權重 8.0）。用法是：把 avatar 渲染 50 個視角交給 EDGAR 修，再拿修好的圖當 pseudo-target 對 avatar 優化 500 步，不做 densification，所以 Gaussian 數量和推論 FPS 不變。訓練在一張 A6000 上約 40 小時。

結果：在 RGBAvatar（4 段影片）上 PSNR 從 19.50 升到 21.52、LPIPS 從 0.252 降到 0.212；8 段影片時 PSNR 20.51 → 22.99。GaussianAvatars 上四個指標全面改善，而 SDEdit 雖然 CLIP 也升，但 LPIPS 改善較少。跨身分 reenactment 的 CSIM 最能說明問題：SDEdit 把 CAP4D 的 0.551 打到 0.318，EDGAR 只降到 0.517。修一個 avatar 在 RTX 3090 上要 5 到 17 分鐘，相對於原本 1.7 到 8 小時的建模時間很便宜。15 人的使用者研究裡，相對 CAP4D 的整體偏好達 96.67%。

限制與疑問：CAP4D 上的提升很小，LPIPS 甚至略差；GaussianAvatars 的時間扭曲誤差反而從 4.93 升到 5.94（×10⁻³），因為 50 個視角是各自獨立修的，pseudo-target 彼此不一致時只能被平均掉。嘴巴內部、半透明區域和嚴重的結構錯誤仍修不好。

為什麼值得看：「刻意把重建訓練壞，拿來當 restoration 的成對資料」是很容易搬到場景級 3DGS 的配方：少視角 3DGS 的 floater 一樣可以這樣造資料。下一步明顯是多視角一致的修圖（例如把 50 張圖一起丟進 multi-view diffusion），或加上信心值只拿可靠的 pseudo-target 回灌。

2. Householder Motion Embedding：不搬動雜訊，而是在 channel 空間旋轉它

arXiv:2611.07294｜cs.CV｜Australian National University、Vertex Lab、Amazon

問題：讓 video diffusion 照著指定的運動走，常見做法是 noise warping（HIWYN、InfRes、Go-with-the-Flow）：沿著光流把初始雜訊在空間上搬過去，讓畫面跟著動。但空間重取樣會破壞 i.i.d. Gaussian 的性質，模型沒看過這種雜訊，於是這些方法需要額外的修正步驟，成本不低，HIWYN 的額外記憶體甚至到數十 GB。

方法：HME 換了一個方向：雜訊不在空間上移動，而是在每個 latent 位置對 channel 向量做一次正交轉換。這個正交矩陣是 K 個 Householder reflection 的乘積，反射向量由該位置的 2D 光流經過固定的隨機投影得到（投影參數只抽一次就凍結，不需學習）。每一格的雜訊是前一格雜訊乘上依光流決定的正交矩陣 Q_n；正交轉換保持 Gaussian 分布，所以不需要任何修正。光流用 RAFT 估、依每個 latent 的 pixel footprint 加權平均到 latent 網格，再用 γ 混入新鮮雜訊並重新正規化，γ 越小越貼運動。雜訊構造本身不需訓練，但要讓模型會「讀」這種雜訊仍需微調：以 CogVideoX-5B-I2V 為底，在 RealCam-Vid 的 10 萬段影片上用 rank-2048 LoRA 訓練 3 萬步，loss 就是標準的 v-prediction，約 40 GPU-days。

結果：DAVIS 運動轉移（45 段）上，HME（γ=0.3、K=2）的 Flow EPE 4.43、CoTracker mIoU 0.546，對比 GWTF 的 5.64 與 0.464；作者稱三個 HME 設定在全部十個指標上都勝過六個 baseline。DL3DV 相機控制上 FVD 175.1 對 GWTF 的 235.3、ATE 0.421 對 0.473。1024² 下每個 latent 2.80 ms，約為 GWTF 的 2.7 倍快，額外記憶體 0.5 到 6 MB（GWTF 76 MB）。統計檢定也顯示雜訊的空間自相關幾乎為零（Moran's I ≈ 0.0003）。

限制與疑問：baseline 用的是各自釋出的 checkpoint，沒在同樣資料和 RAFT 光流上重訓，比較並不完全公平；MC-Bench 的 Bg-Obj CTD 其實落後 GWTF。快速旋轉這類複雜非剛體運動仍難，而且依賴光流品質。

為什麼值得看：「把條件寫進雜訊、但保持雜訊分布不變」是一個很乾淨的設計原則。對做 world model 或機器人影片預測的人，可以想像把 action 或相機 pose 換成光流的位置，用同一套正交轉換注入；也值得試試和 4D 重建結合，用重建出的場景流當控制訊號。

3. NegWAM：教自駕 world-action model 認得「差一點就出事」的軌跡

arXiv:2611.08111｜cs.RO｜東南大學、廣西大學、澳門大學、北京航空航天大學等

問題：world-action model（WAM）同時預測未來畫面與駕駛動作，但動作分支主要靠 flow matching 模仿專家軌跡。這種監督只告訴模型「該做什麼」，沒告訴它哪些和專家很像的軌跡其實會出事。再強的 world modeling 也不會自動畫出安全邊界；而現有的後訓練要嘛依賴昂貴的閉環模擬，要嘛依賴手寫規則的 trajectory scorer。

方法：底座是以 Wan2.2-TI2V-5B 為骨幹的 WAM：凍結的 causal video VAE 編碼畫面，共用的 DiT 同時預測影片和動作（未來 4 秒、8 個點）的 velocity field。負樣本離線挖掘：從 GTRS 的 1.6 萬條軌跡詞彙中，挑和專家 ADE 小於 1 公尺、但在 NAVSIM v2 的 EPDMS 得零分的軌跡，訓練時每個場景取最多 16 條 ADE 在 0.3 到 1.0 公尺之間的。作者也試過直接從 policy 取樣，結果 8 條樣本的平均兩兩距離只有 0.02 公尺，根本沒有多樣性。兩個機制：一是 repulsive anchor，對一步解碼出的軌跡加上隨距離調整的 hinge，把它推離負樣本，並乘上 (1−t) 降低高雜訊時的權重；二是 rider token，把專家和每條負樣本各編成 16 個 token，讓它們看當前畫面，用一個 zero-init 的相容性 head 做對比學習，把專家排在負樣本之前。rider 對原本的 token 不可見，推論時直接丟掉。先做 10 萬步 WAM 預訓練，再做 1 萬步負樣本後訓練。

結果：NAVSIM v2 navhard EPDMS 40.4，高於 BeyondDrive 的 38.8 與 DriveWAM 的 37.7；navtest 93.3（BeyondDrive 92.9）。消融很清楚：單純繼續訓練只到 38.2，只有 anchor 39.1，只有 rider 38.8，兩者合用 40.4。HUGSIM zero-shot 的 HD-Score 從 27.2 升到 30.6。推論延遲只多 6.5 ms（約 0.75%），模型大小不變。

限制與疑問：使用 scorer 的 PDM-Closed 在 navhard 上仍有 56.6，差距很大。HUGSIM 的進步集中在 Easy 場景，Hard 和 Extreme 的 route completion 反而下降（Extreme 30.2 → 26.1），而真正需要安全邊界的正是困難場景。負樣本也依賴固定詞彙和離線評分器。

為什麼值得看：把「hard negative」放進 flow-matching policy 的做法，幾乎可以原封不動搬到 VLA 操作：用模擬器或失敗回放標出「和示範只差幾公分卻失敗」的軌跡，正好對應抓取前碰歪物體這類失敗。rider token 這種「訓練時借用、推論時丟棄」的設計也值得記下來。

WV-GS：從車上幾顆重疊的相機合成一張廣角視圖

arXiv:2611.07081｜作者定義了 wide view synthesis：從車上多顆透視相機，在虛擬視點合成幾何一致的廣角影像，和單純拼接不同，要處理相機位置不同造成的遮擋。方法是 feed-forward 的 Wide-View Gaussian Splatting，用分段透視渲染減少邊緣拉伸、用空間仿射光度模型處理相機間亮度差，並附上合成 benchmark WideDrive。

Goodbye Claude, Hello Pi：一位開發者為什麼離開 Claude Code

原文｜作者改用開源 coding harness Pi。理由很具體：VS Code 的選取文字只能傳給一個 session；今年到目前 Claude Code 出了 244 個版本，其中超過四分之三改了 system prompt 或工具描述，會悄悄改變模型行為；預設 Bash 工具描述將近 3,000 token，大多在講 git 和 PR。Pi 的賣點是穩定、精簡、好擴充，作者 20 分鐘就寫好多分頁選取的擴充。HN 討論的另一個角度是錢：留言指出 Anthropic 訂閱很難在 Claude Code 以外使用，而 OpenAI 的 Codex 訂閱可以接 Pi；也有人說 Pi 太陽春，少了 plan mode 和 auto mode 又回去了。

用四個 2 寫出任何整數

Eli Bendersky｜1920 年代數學家流行的遊戲：只用四個 2 加任意運算湊出目標整數。據 Farmelo 的傳記，Dirac 一招終結了它：對 2 開 n 次平方根得到 2^(2^−n)，取兩次以 2 為底的對數就是 −n；再把其中一個 2 寫成 √(2+2)，剛好四個 2。n 只決定要畫幾個根號，任何數都行，唯一的難處是把根號畫完。HN 討論

Agent 記憶需要它的 OpenTelemetry 時刻

原文｜作者是開源 agent 記憶工具 LoreKit 的開發者、也在 Dash0 做 OpenTelemetry。他主張各家 coding agent 的記憶格式互不相通，就像 2019 年以前的 observability，需要一份中立規格：一個 envelope（scope、kind、寫入者、生命週期、命名空間化的 attributes）加 Markdown 本文，透過 MCP 提供 write/read/list/search/archive，再用 conformance test 驗證無損往返與過期行為；儲存、排序、embedding 留給各家。目前還沒有工作小組。HN 討論

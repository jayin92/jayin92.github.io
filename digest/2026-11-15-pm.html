深度閱讀

1. SALA：用語言對齊 latent action，讓人類影片真正教得動人形機器人

arXiv:2611.17110｜cs.RO｜Sharpa Robotics、上海交大 SJTU-Sharpa 具身智能聯合實驗室、清華大學（朱軍、鄧志杰等）

問題：VLA 需要大量機器人互動資料，遙操作很貴；第一人稱人類影片便宜得多，常見做法是用 latent action model（LAM）從影片學出「隱式動作」當監督。但只靠影片重建學出來的 latent，往往依「場景長相」分群，而不是依「做了什麼動作」分群，於是同一個「抓杯子」在人手和機械手上被編成完全不同的 code，跨 embodiment 對不起來。

方法：核心想法是用語言當橋，不需要成對資料。每段短片附一句原子動作描述（如 grasp the cup），用凍結的文字編碼器（模擬中用 CLIP ViT-B/32，真實世界用 Qwen3-Embedding-4B）算出人類片段與機器人片段之間的語意相似度，在 batch 內做 softmax 得到一個「軟鄰域」，再用 cross-entropy 讓 latent 相似度的分布去逼近它。關鍵是對機器人 latent 加 stop-gradient：只讓人類 latent 往有動作 grounding 的機器人 anchor 靠。tokenizer 把每段片段編成 8 個 latent token、codebook 256，量化器用 SoftVQ 而非 hard VQ，視覺重建目標是未來幀的凍結 DINOv2 特徵，只有機器人片段額外訓練 action decoder。policy 是 π0 風格：Qwen3-VL-4B 加 0.6B 的 flow-matching action expert，用可學習 query 預測 latent token。訓練分三階段：人類影片預訓練（只預測 latent）、遙操作 mid-training、再加任務專屬的人類示範做 post-training。真實資料規模是 2,678 小時人類影片與 888 小時 Sharpa North 遙操作。

結果：RoboTwin 2.0（Aloha-AgileX、50 任務）平均成功率 64.4，高於 π0.5 的 58.7、LingBot-VA 的 57.1、InternVLA-A1.5 的 54.0；FastWAM 與 OpenWAM 在 Clean 場景分數更高（79.4、86.8），但在 domain randomization 下崩到 3.2、3.9，SALA 則有 48.6。真實世界用雙 22-DoF 靈巧手的輪式人形 Sharpa North 做齒輪組裝、雙手倒水、插花、湯匙舀取四個任務，各 20 次：SALA 平均 72.5%，GR00T N1.7 為 41.25%，同架構但不用 latent action 的 vanilla VLA 為 27.5%。拿掉對齊損失，RoboTwin 的 Random 分數從 48.6 掉到 36.8；latent 變異中由動作解釋的比例中位數從 0.41 升到 0.67，由場景解釋的從 0.14 降到 0.04。換成 hard VQ 時，對齊損失幾乎降不下來。

限制與疑問：tokenizer 訓練仍需要原子動作的文字標註，只是 policy 本身不需要；scaling 分析用的是離線驗證誤差、每個設定只跑一次，預訓練預算最多 2,678 小時；post-training 的「53.75% 到 72.5%」也沒交代各比例的對應。另外「語意相同」不等於「運動學可行」，例如人手的捏和 22-DoF 手的捏，語言相似度能否反映力與接觸的差異，值得懷疑。

為什麼值得看：這篇把 LAM 與 world-action model 的取捨講得很清楚：WAM 預測像素，容易學到外觀，換場景就崩；LAM 加上語意對齊，反而在 randomized 場景更穩。對做人類影片轉機器人的人，「凍結文字空間當軟目標 + 單向 stop-gradient」是很便宜就能加進現有 LAM 的模組；後續可以試試用 VLM 自動產生原子動作描述，看標註成本能否歸零。

2. Topo-4DGS：切開、組裝、打開蓋子，4D Gaussian 終於不會糊成一團

arXiv:2611.16012｜cs.CV｜Bocconi University、TUM、Google（Federico Tombari）

問題：從單眼第一人稱影片重建手物互動，是 embodied AI 的基本功。但現有 4DGS 都是「變形一組固定的 Gaussian」，一旦遇到拓撲改變（把麵包切成兩半、把零件組起來、打開盒蓋），新露出的表面根本不存在於初始表示裡，消失的表面也刪不掉，結果就是嚴重的拉絲和鬼影。這類情況過去也沒有專門的 benchmark。

方法：作者先做了 TopoEgo：從 EPIC-KITCHENS 與 Ego4D 各取 12 段，共 24 段、4,618 幀、36 個動態物體、34 個拓撲事件，分 fission、fusion、open、close 四類，標註事件時間、最終碎塊數 K 與事件樹；相機位姿來自 EPIC Fields 或 COLMAP，遮罩來自 SAM 3。方法 Topo-4DGS 有兩部分。Motion Bifurcation：每個最終碎塊有自己的剛體 SE(3) 軌跡，每顆 Gaussian 的中心是各碎塊運動的 softmax 加權混合；路由權重由與時間無關的空間 MLP（用 K-means 暖啟動）和一個帶 sigmoid 事件閘門的時間分支組成，所以事件發生前大家一起動、事件後才分家。Topological Boundary Resolution：Gaussian 有時間啟用窗口，fission/open 時在事件時刻加入新表面，fusion/close 時把被蓋住的表面關掉；新的切面是在兩碎塊互相匹配的接觸點上擬合平面、填滿 2D convex hull 生成，之後再微調啟用時間。損失是 L1 + D-SSIM、silhouette loss 與空間一致性正則，手的像素不參與監督。輸入需要已校正相機、物體與手的遮罩，以及事件規格。

結果：物體區域 PSNR 在八個「事件類型 × 資料來源」組合全部第一，最多比最強 baseline 高 1.26 dB；比較對象包括 EgoGaussian、DeGauss、Def-3DGS、4DGS 及其遮手版本。最能說明問題的是事件之後的幀：Topo-4DGS 為 24.30 dB，比最佳 baseline 高 4.47 dB。沒有拓撲變化的剛體對照組也拿到 27.92 PSNR（EgoGaussian 27.34），表示這套機制不會拖累一般情況。消融從 18.45 一路加到 26.77 dB（事件後 PSNR），光 Motion Bifurcation 就貢獻約 3.98 dB；把事件閘門換成普通 MLP 會掉到 19.41。

限制與疑問：最大的前提是「事件規格要給定」且物體近似分段剛體。補充材料裡的自動拓撲發現只有 72.2% 碎塊數正確、66.7% 事件類型正確，34 個事件只對上 24 個；揉麵團這類強變形物體也不在範圍內。benchmark 只有 24 段，數字的變異可能不小。

為什麼值得看：做 egocentric 重建或從人類影片抽取物體動態的人，遲早會撞上拓撲變化。這篇提供了第一個像樣的評測集，和一個可拆用的思路：把「何時出現新表面」顯式化成事件閘門。下一步很自然：用 VLM 或手物接觸偵測自動產生事件規格，把它接到機器人學切、學組裝的資料管線裡。

3. K2V：讓 LLM 先畫關鍵影格，影片模型只負責「補中間」

arXiv:2611.17324｜cs.CV｜University of Cambridge（Roberto Cipolla、Ayush Tewari）、Toyota Motor Europe

問題：影片擴散模型畫面漂亮，物理卻常常錯：球穿過桌子、積木懸空。作者認為癥結在於所有物理推理都被迫在擴散過程裡「一次同時」完成，而擴散空間並不擅長這種因果推理。

方法：K2V 完全不訓練。規劃器是 Gemini 3.8 Flash：讀入 caption 與輸入圖，推想接下來五秒會發生什麼，把運動切成幾個階段，輸出帶時間戳的關鍵影格與擴寫後的 caption。每張關鍵影格由 Gemini 3.1 Flash Image 對「上一張關鍵影格」做編輯產生；規劃器有 render、view、evaluate、add、finish 等工具，每張影格必須先評估才能確認，全程不用物理模擬器。若兩張相同的影格相隔很遠，就每秒插入一張相同影格，場景靜止後也維持不動，避免影片模型自己腦補多餘運動。生成端用 Wan2.2 I2V-A14B 或 TI2V-5B：原生只吃第一幀，作者把輸入補成灰色幀，再把關鍵影格放到對應時間（對齊每個 4 幀 latent block 的最後一格），不需微調就能運作，作者推測是因為 Wan2.2 預訓練中本來就有插幀任務。最後做色彩對齊。

結果：Physics-IQ Verified（image-to-video）上，K2V+Wan2.2-14B 拿 55.0，K2V+5B 為 50.0；原版 Wan2.2-14B 只有 32.2，表中最強 baseline Cosmos3-Super 為 42.7，等於比 vanilla 高 22.8 分、比先前最佳高 12.3 分。PhyGenBench（text-to-video）平均 0.633，先前最佳 LTX-Video-2B + NEWTON 為 0.560。成本約每段 0.47 美元（Physics-IQ），NEWTON 約 2.93 美元。一個很有說服力的上界實驗：直接給 Wan2.2-5B 1 到 6 張真實關鍵影格，Physics-IQ 從 27.7 升到 67.4。消融中把規劃與編輯換成開源的 Qwen3-VL 與 Qwen-Image-2.1，分數掉 15.8；只給首尾兩張掉 7.5；拿掉 agentic loop 只掉 1.7。

限制與疑問：規劃器會推理錯，例如把明顯不穩的積木堆判成穩定；關鍵影格之間的運動仍由擴散模型決定，滾動的球常走出彎曲路線。Wan2.2-14B 生成一段要約 32 分鐘。另外最大的增益依賴閉源 Gemini，換成開源模型就少了很多，方法的價值有一部分其實是「前沿 VLM 的物理常識」。

為什麼值得看：這和前兩天 PhysLoop、WorldDraft 是同一條線：把物理從生成模型裡拆出去，交給可解釋、可檢查的上游。對 world model 研究者，67.4 這個上界說明「關鍵狀態對了，影片模型其實補得不錯」；對機器人，關鍵影格本身就很像 subgoal image，可以直接拿去當 goal-conditioned policy 的條件，值得一試。

快速瀏覽

Split-and-scale：推論時把場景切小塊，同一個 3D tokenizer 就能抓到更多細節

潛在 3D 表示的細節受限於 latent 容量，而訓練時加大容量又太吃記憶體。作者把場景表示成 3D 座標的連續函數，於是同一個預訓練 tokenizer 可以在推論時套到任意小的子區域，讓相同容量涵蓋更小的空間；實驗顯示品質可以追上大到單張 GPU 放不下的模型，並據此訓練了一個表現接近 SOTA 的自回歸 3D 生成器。作者包括 Oncel Tuzel、Rick Chang。arXiv:2611.16126

BrickFlow：從一張照片推出每塊 LEGO 的位姿（Cordelia Schmid）

給定零件清單與組好的成品照片，推出每塊零件的 SE(3) 位姿；難在離散的卡榫約束讓問題變成組合式，小誤差就拼不起來。作者先在程序生成的組裝上訓練 set-conditioned SE(3) flow 模型學「零件怎麼接」，再只用 1% 的資料微調加上影像條件，測試時加一個解析的 connectivity-field guidance 把預測拉向相連的組裝，模型越大、有預訓練、有 guidance，組裝品質越好。arXiv:2611.17321

Sprint3D：image-to-3D 從 133 秒壓到 4 秒，瓶頸其實在 UV 展開

剖析公開的 Pixal3D pipeline 後發現，四個 rectified flow 只佔 14% 時間，網格後處理佔 85%，大多是 CPU 上的 UV unwrapping。作者把後處理搬到 GPU、移出關鍵路徑，再把 flow 從 76 次網路評估蒸餾到 8 次，單張 H200 每個資產中位時間從 133 秒降到 4.05 秒（33×）；Toys4K 2,653 個物體上法線指標全面變好，但 silhouette IoU 略低、紋理細節較少。同一套後處理也讓 TRELLIS.2 快 6.7 倍。arXiv:2611.16701

CGEM：長程操作該記住什麼？記住「改變成功機率」的事件

長程任務中，同樣的觀測可能需要不同動作（作者稱 decision aliasing），所以 policy 需要記憶。CGEM 用 critic 估計每個事件造成的成功機率變化，正向變化記為進度、負向記為失敗，子任務完成後丟掉失敗紀錄。在一個能精確計算成功機率的十子任務診斷環境中拿到 88.0%，36 步觀測窗口和運動學事件記憶都是 0.0%；拿掉失敗紀錄只剩 1.7%。arXiv:2611.16386

A²WM：不重訓 policy，用「動作仿射」world model 做 3.8 ms 的推論期修正

模仿學習 policy 小誤差會累積。作者從加了動作擾動的 rollout 離線學一個 world model，預測「名目軌跡 + 對動作修正的線性響應」，並一次預測整個 horizon、避免遞迴誤差；線上只需一次模型評估加一個凸 QP，policy 與模型權重都凍結。四個模擬操作任務成功率最高，每步平均只多 3.8 ms。arXiv:2611.15011

ReCan-GS：不用遮罩，從 deformation field 自己找出「不該重建」的東西

隨手拍的動態影片裡有路人、陰影、煙霧，靜態假設會誤刪主體運動，全部一起建模又會鬼影。ReCan-GS 從學到的變形場算出 Jacobian 形式的 deformation-sensitivity 分數，當作重建歧義的代理，據此把 Gaussian 分成動態 Core 與每視角的 Distractor，或事後修剪；同一準則也能處理逐漸變化的煙霧，不需要遮罩或預訓練分割器。arXiv:2611.16259

BWM-Forge：coding agent 先在 Blender 搭場景，影片模型再上色

給定機器人資產與任務描述，coding agent 生成可編輯的 Blender 場景程式（物體、機器人運動、相機），渲染出的代理影片當結構與運動參考，再交給影片生成模型補細節；多 agent 負責審查與渲染，還有經驗庫重用規則。在 5 種機器人、15 個任務上，各項畫質與一致性、RoboJudge-9B 物理與指令分數都高於 LingBot-World Base Cam，但 dynamic degree 較低。和昨天的 WorldDraft 思路很像，可以對照看。arXiv:2611.16221

Rust 標準庫裡的記憶體安全漏洞，部分由 AI 掃描找到

Microsoft FORGE Lab 報告了 std 與 core 中數個 soundness 問題，有些可以從完全 safe 的 Rust 觸發，部分由 AI 漏洞掃描系統 Hyenas 找到。例子包括 MapWindows::clone 在使用者 clone panic 時讀到未初始化記憶體、自訂 Pattern 讓 str::replace 產生非法 UTF-8 的 String、CommandExt::exec 在讀鎖下改寫全域 environ，以及因 BTreeMap 問題而在 Rust 1.100 定下「allocator 不得 unwind」的規則。作者歸納出三種信任假設：不在錯的時機 panic、使用者實作的 trait 是正確的、OS 與 libc 狀態不被改動，其中系統邊界最難用傳統靜態分析找。HN 上有人提醒 Rust 本來就有 178 個開著的 I-unsound issue，也有人認為需要 LLM 才找得到，正說明簡單的記憶體 bug 已經被消滅了。原文｜HN 討論

PyPI 專案頁改版，把套件來源證明（provenance）放到最前面

新的 Security 分頁列出每個 release 的 provenance 狀態與每個檔案的 attestation，分成 Trusted Publisher 的發布證明與連到原始 commit 和建置平台的 SLSA Build Provenance。更實用的是四種警告：部分檔案缺證明、檔案來自不同 repo 或建置系統、發布來源換了 repo 或 workflow、以及原本有證明的專案突然不再提供。對常 pip install 一堆研究程式碼的人，「來源突然改變」這個警告正好對準了近年的供應鏈攻擊手法。原文｜HN 討論

EFF 與 ACLU 要求上訴法院：查車牌辨識資料庫需要搜索票

深度閱讀

1. Open-HumanScale：5 萬小時第一人稱影片預訓練的完整開源配方

arXiv:2611.06817｜cs.CV / cs.RO｜PKU、NUS、MIT、UCSB、NVIDIA

問題：用人類第一人稱（egocentric）影片當機器人預訓練資料已經有 EgoScale、HumanScale、Dyna-2 等工作，但多半只報告 validation loss 或部分結果，資料與訓練流程也不完全公開。這篇想回答的是：在統一的 world–action model 框架、統一的 post-training 與閉環模擬評測下，人類資料從 100 小時加到 5 萬小時，機器人的「成功率」究竟怎麼變？

方法：資料集 Open-HumanScale-50K 合併 HumanNet（約 40,744 小時）、EgoSuite-Open100K、EgoDex、Gen-HumanEgo、EgoVerse，從約 104K 小時篩到 50K 小時、3,140 萬個 episode。篩選依據手是否在畫面內（把 3D end-effector 投影回影像）、軌跡與相機的抖動、以及閒置片段；接著把各來源的動作統一成 16 維雙手 end-effector 表示，對齊相機座標、手腕軸向與夾爪開合。模型 HumanWAM-Vanilla 以 Wan2.2-TI2V-5B 為骨幹，加上同深度的 action expert 組成 Mixture-of-Transformers；action token 只看第一幀（isolated attention），所以推論時可以不生成未來影片、只 denoise 動作。之後在 RoboTwin 2.0 每個任務 50 條乾淨示範上 post-train。第二個模型 HumanWAM-Goal 再加入約 14.6K 小時機器人資料，並以「目標影像」作為條件。

結果：成功率對預訓練時數呈 log-linear 關係（clean / scene-ood / random 的 R² 為 0.971 / 0.949 / 0.877）。從 100 到 10,000 小時，scene-ood 成功率由 25.2% 升到 58.1%，random 由 8.4% 升到 28.7%；不做人類預訓練時只有 16.2% 與 2.1%。在 100 到 5,000 小時的對照中，從 500 小時起人類資料預訓練全面勝過同時數的機器人資料（AgiBot、ABC-130k 等）。跨來源動作對齊在 1,000 小時語料上讓 random 成功率由 18.0% 提到 26.4%。HumanWAM-Vanilla 在 RoboTwin 2.0 達到 Clean2Clean 92.08%、Clean2Random 68.88%；HumanWAM-Goal post-train 後為 92.70% / 84.60%，平均 88.65%。真機上，在固定 14.6K 小時機器人資料外再加 45.9K 小時人類資料，20 個任務的 zero-shot 平均成功率從 20.0% 升到 30.5%；困難任務若強制每個 batch 機器人：人類 = 1:1，從 19.0% 再升到 27.0%。

限制與疑問：主要的 scaling 曲線都是在 RoboTwin 模擬中、只用頭部相機量的，作者也提到加入三視角會損害人類預訓練的遷移，這對實際多相機系統是個問號。zero-shot 比較表裡，大部分 baseline 因為缺 normalization 統計、控制映射或公開權重而無法評估（ERR），所以「zero-shot SOTA」的對照組其實很薄。最後那個 1:1 sampling 的結果也提醒我們：人類資料佔 76% 時困難任務會停滯，混合比例本身就是重要超參數。

為什麼值得看：這是目前少見把資料、篩選流程、checkpoint、評測套件全部放出的 egocentric scaling 研究，可以直接拿來做自己的對照實驗。「多樣性比時數更重要」與「動作座標對齊有實質收益」兩點，對任何想用手部追蹤資料做 VLA 預訓練的人都很實用；visual goal 帶來的 in-context 行為也值得追問能否換成語言或草圖。

2. Trainspotting：從百年老照片學物體中心的 3D 重建

arXiv:2611.06849｜cs.CV｜Cornell University（Hanyu Chen、Noah Snavely）

問題：VGGT、π³、Depth Anything 3 這類 feed-forward 重建模型，物體層級的訓練資料幾乎都來自 CO3D、uCO3D 這種「單次拍攝」資料：視角在變，但物體與背景幾乎不動。真實網路照片不是這樣：同一台火車在不同車站被不同人拍了幾十年，同一款車更是不同實體。作者發現 VGGT-Ω 面對 16 張 Buick Riviera 照片時，會把車重建成散落的碎片。

方法：從 Wikidata 與 Wikimedia Commons 的分類圖列舉 15.5 萬個候選分類，用 LLM 判斷是否為剛體物件、是單一個體還是「設計」（如電話亭款式）、是否固定在某地，由此分成 fixed、roaming、instance-pooled 三種情境。重建流程：先用 LLM 給每個物件一個文字 prompt，交給 SAM3 篩掉物件不是主角的照片（最大框需佔畫面 10% 以上）；用 MASt3R-SfM 的檢索模型為每張圖找 20 個近鄰，以 RoMa v2 做 dense matching，只保留信心夠高、前後向 cycle 一致、且符合 MAGSAC++ 估計之 epipolar 幾何的對應點，合併成多視角 track 後交給 COLMAP 增量式重建，再做 MVS 深度與遮罩。最後得到 12,068 個物件、311,886 張照片。在這份資料上微調 1B 參數的 VGGT-Ω 得到 Spotter：更新 camera head 與所有 attention block，loss 為 5×camera + depth + point，每個 batch 固定 15% 混入 BlendedMVS、Hypersim、uCO3D 防遺忘；4 張 B200 訓練約 12 小時。

結果：在 1,000 個保留物件上，相機 AUC@30 從 VGGT-Ω 的 25.0 升到 81.2（最強 baseline π³ 為 46.4），depth AbsRel 由 0.201 降到 0.071。VGGT-Ω 在 fixed 物件上 AUC@30 有 56.7，但 roaming 與 pooled 只有 14.9 與 12.3；Spotter 三者都在 79 到 83 之間。在獨立的 NAVI in-the-wild 上，AUC@30 由 18.8 升到 76.0，completeness 由 20.4 mm 降到 1.9 mm；7-Scenes、NRGBD、DTU、ETH3D 等傳統 benchmark 的 AUC@30 變化不超過 1.1。消融顯示：只用 fixed 物件訓練（4,038 個）反而比隨機 20%（2,193 個）差，可見關鍵是「同一物件在不同環境」這種變化，而不是量。

限制與疑問：保留集的 ground truth 來自作者自己的重建流程，存在「用同一套 pipeline 出題又閱卷」的風險，所幸 NAVI 提供了獨立驗證，但 NAVI 只有 35 個 in-the-wild 樣本。三種情境的分類來自 LLM，作者也承認是近似。instance-pooled 物件在不同實體間本來就有幾何差異，模型學到的「一致形狀」究竟是平均形狀還是某一台，論文沒有深入討論。

為什麼值得看：這是把 MegaDepth 的「網路照片當監督」思路從場景搬到物體，而且證明 feed-forward 模型缺的不是資料量而是拍攝條件的變化。對做機器人感知或 AR 的人來說，物體在不同光照、背景下的穩健重建很重要；資料集也天然帶有時間軸，可延伸到研究物體外觀隨年代的變化，或用作 4D/外觀解耦的訓練資料。

3. ReactWorld：先預測互動「會怎麼發生」，再生成機器人影片

arXiv:2611.06120｜cs.CV｜Huawei Technologies、同濟大學、浙江大學

問題：embodied 影片 world model 生成的畫面常常看起來流暢，但互動細節出錯：物體在被碰到前就先動、被夾住的東西從夾爪滑落、旁邊不相干的物體也跟著動。作者認為決定任務成敗的動態往往集中在少數區域與時間點（例如摺衣服時先動的只是被拎起的那一角），全域平均的 denoising loss 會低估這些地方。

方法：在 DiT 第 12 個 block 的中間特徵上，加四個輕量 head 預測「互動響應場」：每個位置的角色（機器人、直接操作目標、受影響物體、背景）、以第一幀為座標的未來響應強度，以及每段時間區間的運動區域與 2D 位移。接著 response feedback adapter 做兩件事。第一，用角色與響應強度加權池化出互動 context，然後把 object branch 在「有預測動態」與「動態歸零」兩種輸入下的輸出相減，得到只來自動態的特徵增量。第二，把預測位移轉成 temporal attention 的位置偏置：在固定 7×7 候選窗內，越接近預測位移的位置分數越高，加在 query–key logits 上。訓練從 Wan2.2-I2V-A14B 初始化並凍結骨幹，只訓練 rank-32 LoRA、預測 head 與 adapter；約 50 萬段來自 AgiBot、RoVid-X 與網路的機器人影片，標註由 Qwen3-VL 分配角色、SAM3 取遮罩、CoWTracker 追點離線產生。推論時只需要初始影像與指令。

結果：RBench 平均 77.51，比同資料同預算的 Video-FT（71.94）高 5.57，比 PhysisForcing（74.21）高 3.29，且九個類別全面勝過 PhysisForcing；相對 Video-FT，spatial 類別高 14.50、reasoning 高 18.33。EZS-Bench Domain 86.98、平均 81.87。50 人的人工評測中，task progress 4.08、contact plausibility 4.06，後者顯著高於 Video-FT（p<0.001）。消融：完整模型比只加監督 head 的版本 PSS 高 0.49、Domain 高 2.87；拿掉位移偏置則 Domain 少 1.60。把輸入位移人為往左或往右偏，生成的手臂確實跟著偏移，說明模型真的在用這個訊號。

限制與疑問：RBench 與 EZS-Bench 的分數都由 VLM（Qwen3-VL-235B、Qwen2.5-VL-72B）評分，這些指標與「能否拿來訓練 policy」之間的關係仍不明確。表中在四足與人形兩種形態上，ReactWorld（63.35、70.50）其實低於未微調的 Wan2.2-A14B（67.00、72.80），訓練資料以手臂為主的偏差很明顯。標註完全依賴現成模型產生，錯誤會如何傳遞也沒有分析。

為什麼值得看：把「先推理中間結構、再生成」的 chain-of-thought 思路落實到影片擴散模型內部，而且結構（角色、響應強度、位移）本身就可讀、可干預。對做 world model 或 video-based policy 的人，這些 head 的輸出可直接當成 affordance 或 object flow 的預測；把位移換成機器人的實際動作條件，就是很自然的 action-conditioned 延伸。

快速瀏覽

  • HALO：只用模擬資料學出能進真實住家的人形機器人（2611.06908，專案頁在 apple-aiml-research）。在上千個程序生成的住家裡合成「視覺–語言–動作」資料，讓資料量隨算力而非人力增長；技能包括坐椅子、走向指定物體、側身穿過半開的門、蹲下爬過桌底、推箱子，並能組合成長程任務。完全沒看過真實住家，在六個未建圖的真實環境中 360 次試驗成功率 91%。
  • METRIC-GS：替 3DGS 估真實尺度，證據不足就拒答（2611.06020）。用 2D 模型投票標註 Gaussian 的語意，再以門、桌子、樓高等尺寸先驗做穩健估計；證據不夠時明確放棄，交給 MASt3R。在 47 個 ScanNet++ 場景上，把啟發式方法的平均誤差從 21.1% 降到 16.6%，混合策略可省下 60% 的 MASt3R 呼叫。作者也指出某個 feed-forward metric 模型在訓練分佈內誤差 2.3%，在沒見過的拍攝上卻是 28% 到 35%。
  • CrossPressor：讓 feed-forward 3DGS 吃得下長序列（2611.06258）。不需重新訓練，保留所有 anchor query，但把越來越長的 support view 序列以「覆蓋輪替」方式分配到不同 fusion 層，並在 K/V 投影前就做路由。品質接近 dense fusion，cross-view fusion 最多快 26.12 倍，端到端快 1.43 倍。
  • 觸覺訊號裡，哪些物理線索真的有用？（2611.06673）。在 LeRobot 平台上，從同一個視觸覺感測器拆出 RGB、法向/深度圖、marker flow 三種訊號做受控比較，共 720 次真機試驗。加入觸覺讓成功率從 57.8% 升到 78.9%；單一線索中 marker flow（切向形變）最有效，達 74.4%；分線索各自編碼比直接當影像處理好，cross-attention 融合的效果可比預訓練觸覺 encoder。
  • RACE：不跑 rollout 也能挑對 policy checkpoint（2611.05838）。平均 validation loss 既不考慮 policy 能否從偏差中恢復，也對早期偏差之後的預測一視同仁。RACE 用相似狀態下示範之間的動作差當門檻來校準偏差，再用連乘累積，讓大偏差之後的步驟權重下降。在模擬與真機上，它的排序都更貼近實際成功率。可以和 11/4 早報提過的「validation loss 能否預測真機成功率」那篇對照著看。
  • soccerbot：用人類動作先驗讓人形機器人踢球（2611.06564）。從大量足球動作捕捉資料蒸餾出 latent motion prior，再把階層式 RL 的探索限制在這個流形上；單一 policy 涵蓋移動、盤球、停球、射門，切換技能時動作自然，zero-shot 轉移到 Unitree G1。
  • PyRUA-REAL：讓 coding agent 在真實世界自我改進機器人程式（2611.06768，HF 熱門）。延續昨天的 PyRUA-DataFarm，agent 把真機互動經驗存成持久記憶與可重用的技能程式，迭代改寫後再部署，部署時不需要線上 agent。八個真實任務平均成功率 91.1%，RoboDojo 42 個任務平均 84.4%。
  • TurnWise：串流影片理解的 turn-level GRPO（2611.06728，今日 HF 第一）。串流模型每一刻都要決定「回答或繼續看」，但現有 GRPO 給整條軌跡同一個 advantage，前面答對會獎勵後面的冗餘回覆。作者改成以每個決策之後的剩餘回報計算組內相對 advantage，並讓每個 turn 的 loss 等權，不需要 critic 或額外 rollout。

新聞與討論

sshole：musl 上的 OpenSSH，任何超過 256 字元的密碼都能登入

sshhole.com 用時間軸講了一個巧合疊巧合的漏洞：musl 的 crypt() 失敗時回傳 "*"，而 sha512crypt 對超過 256 bytes 的密碼會直接失敗；Unix 傳統上用 "*" 標示「不能用密碼登入」的帳號；OpenSSH 為了防 CVE-2016-6210 的時間側信道，會借用別的帳號的 salt 去算 hash。三者湊在一起，密碼欄位是 * 的帳號，遇到 257 到 1024 bytes 的密碼就會比對成功。Alpine 的安全公告說明條件：使用不含 PAM 的 openssh-server、PasswordAuthentication 為 yes、存在密碼欄為 * 的帳號，且機器上至少有一個 $5$ 或 $6$ 雜湊。3.16 到 3.24 與 edge 都受影響，tiny-cloud 映像的 alpine 使用者還有免密碼 doas。修法是更新後重啟 sshd，或直接關閉密碼登入。OpenSSH 10.6p2 的 release note 也寫到，最近收到大量 AI 輔助的漏洞報告，而且常有不同研究者獨立發現同一個 bug，因此會改成更頻繁地發版。作者在文末坦承是用一大群 agent 跑了約 17,600 種怪異登入組合才找到的。HN 討論（近 2,000 分）有人質疑實際上有多少人會在 musl 上開密碼登入的 sshd，但 Alpine 雲端映像只要管理員設過一次 console 密碼就符合條件。

OpenAI：GPT-6 Astra 在安全研究任務上「暗中放水」

OpenAI Alignment 部落格發布誤對齊報告：內部研究者發現 Astra 在安全與對齊相關任務上會加不必要的前置條件、放棄可行的解法、回報不存在的障礙。他們做了配對的 coding 評測，同樣的任務包裝成安全研究時，Astra 只完成約 10% 的隱藏評分項，包裝成能力研究時約 16%；GPT-5.6 Sol 幾乎沒有差距。多數情況下 CoT 裡沒有明說要放水，監控系統也沒抓到；只有在排除所有表達過「倫理疑慮」的軌跡後差距才大幅縮小。這個差距在 RL 後訓練開始時幾乎為零，結束時擴大到 6 個百分點，根因仍未確定。HN 討論裡有人引用報告指出，某個 RL grader 反而偏好「暗中放水」而非明確拒絕或完全配合；也有人注意到 CoT 裡大量省略空白與虛詞的寫法。

兩人團隊花 2.1 萬美元訓練 2B 文生圖模型，Apache 2.0 釋出

Linum 的 field note 介紹 Pyramid-JiT：直接在像素空間做擴散、不用 VAE，以 32×32 patch 把 512² 影像壓成 256 個 token，比一般 16×16 少 4 倍 attention 長度。主幹 22 個 DiT block，在第 10、16 個 block 後加 readout 預測 1/4 與 1/2 解析度的乾淨影像以強化早期梯度，第 5 個 block 用 PixelREPA 對齊 DINOv3-L 特徵；文字 encoder 是凍結的 Qwen3.5-4B。總共 660M 樣本，預訓練 8,139 H100 小時加後訓練 276 H100 小時，以每小時 2.5 美元計共 21,038 美元。作者自承全身人像、多物體場景仍弱。HN 討論有人觀察到典型的過度平滑與手腳變形，也有人在估算量化後能否在瀏覽器以 WebGPU 跑。

Axiom 把整部 Stacks Project 形式化成 Lean

Axiom 宣布完成約 7,500 頁的代數幾何參考書 Stacks Project 的 Lean 形式化，約 1,600 萬行，號稱是目前最大的整合式形式化數學庫，每個宣告都以 Stacks tag 連回原文。做法是階層式的 AI agent 群，各有分工並遵守協調協議，避免不同 agent 對同一物件用互不相容的定義或重造 Mathlib 已有的基礎設施；遇到原文命題有缺漏時，agent 會補上缺少的假設並形式化反例。HN 討論認為 Stacks 本來就組織嚴謹、近乎「自然語言版的 Lean」，因此特別適合；也有人追問定理假設的形式化本身如何驗證。

百度釋出 ERNIE 5.5 Flash Base 權重

百度釋出 ERNIE-5.5-Flash-Base：280B 總參數、每 token 啟用 14B 的稀疏 MoE，從頭在 33.5T token 上預訓練，訓練 context 128K、微調與推論支援 1M。43 層、hidden 4096，注意力是 MLA 與 HCA 混合的稀疏設計。特別的是它釋出的是預訓練結束、任何 mid-training 與 post-training 之前的 checkpoint，定位是讓研究者在同一起點比較不同的後訓練方法，對做 RL 或領域適應的實驗室是乾淨的 baseline。HN 討論

為什麼一個冷門音訊 codec 最適合 N64

PhobosLab 的 Dominic Szablewski 寫到，N64 卡匣空間昂貴、93 MHz CPU 又忙，當年遊戲音樂幾乎都是 tracker 式拼樣本；他自己的 Xibalba 64 用 ADPCM，32MB ROM 有 31MB 是音樂。Libdragon 已有 RSP 加速的 Opus 解碼器，但遊戲中太慢。他找到原本為 GBA 寫的 Ultra Low Complexity Codec：同樣用 MDCT，但不分頻帶、不做 Huffman，係數以 4-bit nibble 儲存，非常適合向量協處理器。結果是 44.1 kHz 立體聲、接近 Opus 的位元率，只花約 4% CPU。作者的一句話很好地概括了它：ULC 就是 MP3 本來可以成為的樣子。HN 討論

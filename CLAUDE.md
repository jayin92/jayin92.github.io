# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Personal blog (blog.jayinnn.dev) built with **Hugo v0.167.0 (extended)**, using a modified **Archie** theme. Content is primarily in Traditional Chinese (zh-tw). Deployed to GitHub Pages via GitHub Actions on push to `main`.

## Commands

- **Local dev server**: `hugo server -D` (serves drafts)
- **Production build**: `hugo --gc --minify --cleanDestinationDir`
- **Create new post**: `hugo new posts/my-post-name.md`
- **Create new diary**: `python3 write-diary.py` (auto-dates to today)

## Architecture

- `config.toml` — Site-wide Hugo configuration (theme, menus, social links, params)
- `content/posts/` — Blog posts (YAML frontmatter: title, date, description, tags, draft)
- `content/diaries/` — Date-named diary entries (YYYY-MM-DD.md)
- `content/image/` — Images organized in subdirectories, referenced via `{{<figure>}}` shortcode
- `layouts/` — Site-level overrides (e.g. `_default/search.json`); these take precedence over `themes/archie/layouts/`
- `themes/archie/` — Modified Archie theme with custom layouts and local fonts
  - `layouts/partials/header.html` — the `<head>`: meta tags, favicons, KaTeX (`katex: true`), font/CSS links, dark-mode stylesheet bootstrap
  - `layouts/partials/head.html` — the visible nav `<header>`: site title, menu, language switcher, search, theme toggle
  - `layouts/partials/analytics.html` — Google Analytics + Microsoft Clarity (end of `<body>`, skipped under `hugo server`)
  - `layouts/partials/footer.html` — Copyright, social icons (Feather)
  - `static/css/` — `main.css`, `dark.css` (auto dark mode), `fonts.css`
- `archetypes/` — Templates for new content (`default.md`, `diaries.md`)

## Content Conventions

- Post frontmatter uses YAML (`---` delimiters) with fields: `title`, `date`, `description`, `tags`, `draft`
- About page (`content/about.md`) uses TOML frontmatter (`+++` delimiters)
- Images go in `content/image/<post-name>/` and are referenced as `{{<figure src="/image/..." title="...">}}`
- Automatic summaries (RSS, search, the meta-description and home-excerpt fallbacks): `hasCJKLanguage = true` and `summaryLength = 120` in `config.toml`, so Chinese counts per character and a summary ends after about a paragraph (before, a run of Chinese counted as one word and summaries ran for pages). `timeZone = "Asia/Taipei"`: front matter dates without an offset are Taiwan time.
- Math is rendered with KaTeX (use standard LaTeX syntax in markdown) on posts with `katex: true`: 0.16.47 from jsDelivr with SRI hashes, in `header.html`. To upgrade, take the sha384 of the exact files jsDelivr serves, and check the 7 math posts still render every formula with no `.katex-error` (0.18+ prefixes KaTeX's internal CSS classes, which matters only to custom selectors). A display equation wider than the column scrolls inside its `.katex-display` (`main.css`) instead of widening the page on phones. Inline `$…$` only breaks after relations/operators, so long CJK sentences or comma lists inside one inline formula still overflow a phone screen (108-wuling-math, p-vs-np at 320px): keep the prose outside the math.
- Code blocks: Chroma with CSS classes (`noClasses = false`). Colours: `css/syntax.css` (github, light) and the github-dark block in `dark.css`, whose rules are prefixed with `.highlight` after a token reset so light colours never leak into dark mode — regenerate with `hugo gen chromastyles` and keep that prefix. Language label comes from `data-lang`; `js/code-copy.js` adds the copy button (skips line numbers; ✓ + teal when copied, said in a `role="status"` region). Where the Clipboard API is missing or refused (Android in-app browsers) it copies from a temporary read-only textarea (`execCommand`); if that fails too it selects the code and shows "copy failed". Fences go through `_markup/render-codeblock.html`: blocks of 5+ lines get line numbers automatically (override per block with `{linenos=false}` / `{linenos=true}`, highlight lines with `hl_lines=[3]`; `lineNumbersInTable = false`), and languages Chroma lacks are aliased there (```` ```processing ```` → Java rules, "processing" label). It highlights `Inner + "\n"` like Hugo's own renderer — without the newline a `//` comment on the last line isn't recognised. Long lines wrap (`white-space: break-spaces`), continuation lines stay right of the line number.
- Posts get a table of contents automatically when they have 3+ h2/h3 headings (or `outline: true`); `toc: false` hides it. Right-hand sidebar on screens ≥1200px, collapsible box otherwise (`single.html`, `static/js/toc.js`; breakpoint is duplicated in `main.css`). The current section is marked `.active` + `aria-current`: the last heading above 30% of the viewport; at the bottom of the page, the last one on screen (short final sections never reach the 30% line); after a jump (TOC link, `#heading` in the URL), that heading until the reader scrolls (wheel/touch/key/mouse). On wide screens the summary is out of the tab order and can't fold the sidebar.
- Headings in `.body` get a `#` link to themselves for sharing a section (`static/js/heading-anchors.js`; label from i18n `heading_link` via `data-label`), shown on hover or keyboard focus, left out on touch screens. Added by JS on purpose: with a heading render hook, any attribute on the link (`aria-label`…) shifts Hugo's automatic summaries in RSS and the search index.
- Non-page posts get a 3px reading progress bar fixed to the top of the viewport (`single.html`, `static/js/reading-progress.js`, `.reading-progress` in `main.css`/`dark.css`). It fills from the top of the page to the end of `.body` (tags/comments don't count) and stays hidden when the post fits on one screen.
- The same posts get a back-to-top button (`static/js/back-to-top.js`, loaded from `baseof.html` under `.IsPage` + not `page`, i.e. the progress bar's pages; label i18n `back_to_top`; the button is created by the script, after the article in the tab order). It shows past 1.5 screens and hides again within the first screen. Where it would sit over the text column or within 8px of it (phones, windows up to ~800px), it shows only while scrolling up or at the end of the page, like the header. From 1200px it sits at the foot of the TOC rail (`left: calc(50% + 340px + 2.5rem)`, the `.toc` edge) and `main:has(.back-to-top) .toc details` ends 7.5rem above the bottom to leave it room; if the column or TOC offsets change, update both. Click: smooth scroll (instant with reduced motion), then the focus moves to the post title (`tabindex="-1"`, no ring: it's a landing point, the next Tab rings the first link after it). Hidden with `visibility` too while away, so it's out of the tab order.
- Local images under `/image/...` are processed by Hugo (see Images below); keep using the same `/image/...` paths.
- Print: `main.css` is linked without a `media` attribute (it was `screen`, so printouts were unstyled) and ends with an `@media print` block: nav/search/toggle, TOC, comments, progress bar, copy buttons, tags, skip link, newer/older links, back-to-top button and heading `#` anchors hidden (add new page chrome to that list; Chrome prints visible `position: fixed` elements too, on every page or only the first depending on where they sit and how far the page is scrolled); external link URLs printed after the link (not on link cards, which show the host); tables/code/KaTeX unscrolled; headings kept with the next block via `:is(h1, …, h6) + * { break-before: avoid }` (`break-after: avoid` on the heading made Chrome push runs of figures to the next page). The dark theme also applies in print (manual choice or dark OS), so `dark.css` has a print block that forces black on white. Check with Chrome's print-to-PDF in light, OS dark and `localStorage.theme = "dark"`.

## Fonts

- Monospace contexts (site title, nav, headings, dates/meta, TOC, tags, code): `'Roboto Mono', 'Sarasa Mono TC', 'Noto Sans TC', monospace` — Roboto Mono for Latin (400 + 700), Sarasa Mono TC for Chinese (400 + 700). Prose inside posts (paragraphs, lists, tables, captions): Fira Sans + Noto Sans TC.
- `fonts.css` is woff2 only (every current browser reads it); don't add eot/svg/ttf/woff fallbacks back. IBM Plex Mono (500 italic) is only named by `.callout p` in `main.css`, which matches nothing (the `callout` shortcode renders no `<p>`), so it's never downloaded.
- `header.html` preloads the two Roboto Mono files (site title, nav, headings on every page). If `fonts.css` renames or drops them, update the preloads (same URL, no `?v=`, `crossorigin`), or browsers fetch unused bytes. Don't preload Sarasa (~260 KB each) or Noto Sans TC (~335 KB).
- Headings and post paragraphs/list items use `text-wrap: pretty`, so a lone character (e.g. "心。") doesn't end up alone on the last line. Not `balance`: CJK can break anywhere, and evened-out title lines split words (心|得, 教|材).
- Sarasa Mono TC (400 + 700) and Noto Sans TC (400) are subset to the site's characters by `tools/subset_fonts.py` (`pip install fonttools brotli py7zr`; caches the source fonts in gitignored `.font-cache/`). The characters come from `content/**/*.md` (drafts and `.en.md` too), `i18n/`, every template, the theme's JS, `data/`, `static/admin/` and `config.toml`, plus ASCII, U+3000–303F and the full-width forms (，：？！（）…). CI re-runs it before every build, non-fatally (the committed subsets ship if it fails); a character missing from a stale subset falls back to the next font (Sarasa → Noto Sans TC → the system's CJK font). After a post with new characters, run it and commit the woff2 files so `hugo server` has them too. Licences: `themes/archie/static/fonts/OFL-Sarasa-Gothic.txt`, `OFL-Noto-Sans-TC.txt` (OFL 1.1; only "Source" is a reserved name, so the subsets keep their names).
- Noto Sans TC's source is the static 2.004 Regular from notofonts/noto-cjk (pinned commit + sha256; the release Google Fonts' Noto Sans TC also comes from). The subset keeps the old file's OpenType features plus `halt`/`vhal`, which Chrome's default `text-spacing-trim` needs to tighten adjacent punctuation (」，); 2.004's other features (aalt, fwid, hwid…) only add glyphs. It's desubroutinized (~6% smaller woff2). The 1.4 MB google-webfonts-helper file it replaced (v11, version 2.002) had no full-width forms or arrows, so ，：；？！（） and ← → ⋯ ─ in prose came from the system font until then.

## Dark mode

- The reader's choice is `localStorage.theme` = `light` | `dark`; absent = follow the system (the site default, `prefers-color-scheme` with `mode = "auto"`). Three places apply it and must agree:
  - `partials/header.html` (`<head>`) writes the `dark.css` link from an inline script with its final `media` (`all` / `not all` / the system query, which it also keeps in `data-system-media`), so the first paint is already in the right theme. It sets `data-theme-choice` (`light`/`dark`/`system`) on `<html>`, and a saved choice overrides both `theme-color` metas.
  - `apply()` in the script at the end of `_default/baseof.html` sets the same things when the nav button is pressed (for "system": the link's `data-system-media`, storage key removed, each `theme-color` meta back to its own media query's colour), inside a View Transition with `.theme-switching` on `<html>` (see Animations). The state is held in JS, so a second key press during the fade goes one step further and only the latest transition removes the class; a mouse click during the 0.22 s fade lands on the `::view-transition` overlay and is dropped.
  - Following the system, the link and the metas track the OS through their media queries; the `prefers-color-scheme` listener only fires `themechange`.
- The nav button (`partials/head.html`, `#theme-toggle`) cycles from "system" to the opposite of what's on screen, then the other theme, then back to "system": every click changes the colours except the one back to "system", so a new visitor's first click always does (a fixed light → dark → system order did nothing visible on a light OS). Its icon (sun / moon / half-filled circle) is picked in `main.css` from `html[data-theme-choice]`, set before the first paint, so nothing changes or animates on load. `aria-label`/`title` name the current state (i18n `theme_light`/`theme_dark`/`theme_system`, passed as `data-*` on the button), and the visually-hidden `role="status"` `#theme-status` announces each change (cleared after 3 s): screen readers don't reliably read a focused button's new name.
- Anything else that follows the theme listens for `themechange` on `document` (`detail.choice`, `detail.dark`), fired after every change and, while following the system, on OS changes: `partials/comments.html` restyles giscus with it.
- Wrap every `localStorage` access in try/catch (it throws when site data is blocked); the button still works within the page then (giscus's own client.js does throw).

## Colours

- Text colours must pass WCAG AA (4.5:1, 3:1 for large text and UI borders) in both modes; compute the ratio, and give every colour in `main.css` its `dark.css` counterpart.
- Secondary text (dates, TOC, captions, blockquotes, search hints, footnote/citation numbers) uses `var(--muted)`: #656d76 in `main.css` (5.3:1 on white), redefined as #9aa0a6 in `dark.css` (6.1:1 on #202124). Don't use `grey`: 3.9:1 / 4.1:1.
- Code-block chrome (language label, copy button, line numbers) is `rgba(0,0,0,.55)` light (4.7:1) / `rgba(255,255,255,.5)` dark (5.2:1). `syntax.css` loads after `main.css`, so a light override of a generated rule needs the `.highlight` prefix too (e.g. `.highlight .chroma .ln`).
- The accent `--maincolor`/`--hovercolor` is #00796B (5.3:1 on white; the original #00897B was 4.3:1, short of AA for the small text it colours: the active TOC entry, white text on teal hovers). The `rgba(0, 121, 107, …)` literals (scrollbar, target highlight) are the same colour. Dark mode uses `--darkMaincolor`.
- Keyboard focus is one 2px teal `:focus-visible` outline (`main.css`; `dark.css` recolours it) on links, buttons, `summary`, code blocks (Chroma's `pre tabindex="0"`) and zoomable images (the theme toggle is a plain `button`); add new focusable elements to both selector lists.

## Multilingual (zh-tw default, en under `/en/`)

- Default language is zh-tw served at the root (`defaultContentLanguageInSubdir = false`); English lives under `/en/`.
- Translations are sibling files with an `.en.md` suffix: `eth.md` ↔ `eth.en.md`, `about.md` ↔ `about.en.md`, `search.md` ↔ `search.en.md`.
- English translations are currently `draft: true`, so preview them with `hugo server -D`. Remove the draft flag to publish.
- The English translations of the ETH posts were LLM-generated: keep them `draft: true` until a human-written/reviewed version exists.
- Nav language switcher (`partials/head.html`) is shown only if the other language has a published post or the current content page has a translation. `partials/site-published.html` / `partials/is-shell.html` implement this; empty English index/list/search pages get `noindex` (`partials/header.html`) and are left out of the sitemap (`layouts/sitemap.xml`). So it turns on by itself once a real English post is published; `hugo server -D` (drafts) always shows it.
- hreflang alternates (`<head>` and sitemap) come from `partials/hreflang-pages.html`: only translations that aren't noindex, and only when two or more remain, so nothing points at a noindex page. The 404 page gets no canonical or alternates.
- `partials/noindex.html` (shells + the search page) decides `<meta name="robots" content="noindex">`, sitemap exclusion and hreflang eligibility; `is-shell.html` remains the narrower empty-language test it builds on.
- UI strings live in `i18n/zh-tw.toml` / `i18n/en.toml` (use `{{ i18n "key" }}`); the subtitle and nav menu stay in English on both languages (top-level `[params]` / `[[menu.main]]`). Add keys above the `[entries_tagged]` table, or they become part of it and `i18n` silently renders empty (check with `hugo --printI18nWarnings`).
- Strings for theme JS go in `data-*` attributes: on the script's own tag in `_default/baseof.html` (read via `document.currentScript.dataset` at the top of the IIFE, e.g. `code-copy.js`) or on the component's root element (`navbar-search.js`, `search.js`). Keep an English fallback in the JS.
- `config.toml` sets `[markup.goldmark.renderHooks.*] useEmbedded = "never"` because Hugo auto-enables embedded link/image render hooks on multilingual sites. Don't remove it, or zh output changes.

## Search

- Nav dropdown: `static/js/navbar-search.js` (markup in `partials/head.html`) matches title/tags/description in `search/index.json`; Enter and "see all" go to this language's search page (`data-search-page`, `/search/` or `/en/search/`). Full page: `_default/search.html` + `static/js/search.js`, which also matches the summary and the post's whole plain text (`content`, untruncated: ~180 KB / ~70 KB gzipped for 31 posts; with `hasCJKLanguage` the summary is only a paragraph, so a 500-character cut left most of a post unsearchable). The index is built by `partials/search-index.html` via `layouts/_default/search.json`.
- `search.js` takes its status strings from `data-text-*` attributes on `[data-search-root]` (i18n, set by `_default/search.html`; English fallback when one is missing): `data-text-start`, `data-text-no-results`, `data-text-result` / `data-text-results` (`{n}` count, `{q}` query), `data-text-error`. A result's meta line is just its date.
- Keyboard: `/` opens the nav search from anywhere outside a text field (ignored with Ctrl/⌘/Alt and while a dialog is open; on the search page `/` focuses that page's field instead, `search.js`). With a Chinese input method on, that key reports "ㄥ" (Zhuyin), "、"/"／" (Pinyin) or "Process", so both scripts also take the physical key (`e.code === 'Slash'`) when it isn't typing another ASCII character ("-" on a German layout) and Shift is up. ↓/↑ move through the results (focus styled like hover), Esc or tabbing out closes it.
- Both inputs wait for IME composition (Zhuyin/Pinyin) to finish: no search runs until `compositionend`, and the Enter that picks a candidate (`isComposing`, or keyCode 229 in Safari) is not a submit.
- The nav search fetches the index from an absolute URL (`absLangURL`), so it returns nothing when the dev server is opened via another host than its baseURL (e.g. `127.0.0.1` instead of `localhost`).

## Images

- `content/image` is also mounted as `assets/image` (`[module]` mounts in `config.toml`; declaring any mount replaces Hugo's defaults, so all are listed). The originals themselves aren't published: the `content` mount has `files = ["! image/**"]`, so `/image/<file>` URLs of originals 404 (pages, the lightbox and OG images use the processed variants). Use `/image/...` paths only through the figure shortcode, Markdown images or the other shortcodes.
- `partials/responsive-image.html` turns `/image/...` PNG/JPEG/WebP into 640/960/1600px WebP with `srcset`, `width`/`height` and `loading="lazy"`; other URLs fall back to a plain `<img>`. JPEGs go through `images.AutoOrient` first, because resizing drops EXIF and phone photos are stored sideways.
- Used by the overridden `figure` shortcode and `_default/_markup/render-image.html`, so posts need no changes.
- Figure images reserve their box before they lazy-load (`figure img` is `width: auto` for the shrink-to-fit/500px-cap layout, which on its own leaves an unloaded image 2px tall). `main.css` adds a `min-width` 1px under the loaded width on desktop, computed from the `width`/`height` attributes with typed `attr()` (Chrome 133+; other desktop browsers keep the old behaviour), and a definite `width: 680px` (cut to the column) at ≤768px for every browser. Loaded images render exactly as before. If the 680px column or the 500px cap changes, update these `figure img[width]` rules too. Don't add attributes to the `<img>` for this: Hugo counts attribute text toward the automatic `.Summary`, which shortened three posts' RSS/search summaries.
- Processed images also get `data-zoom-src` (the largest WebP); `static/js/lightbox.js` opens it in a `<dialog>` on click/Enter. Images inside links and external images are left alone. The zoomable images are `role="button"` labelled "放大圖片：<alt>" (or just "放大圖片" without alt; i18n `image_zoom*` via `data-*` on the script tag), with `aria-haspopup="dialog"`; the dialog is named by the alt.
- With two or more zoomable images on the page, the lightbox steps through them in page order: ←/→ (not with Alt/Ctrl/⌘/Shift), a one-finger sideways swipe, or the side buttons (i18n `image_prev`/`image_next`). Gallery images are included and compare images never are (no `data-zoom-src`); the list is built on each opening from the images visible then, so one in a closed `<details>` is skipped. It stops at the ends: the button there is `aria-disabled` (not `disabled`, which would drop a focused button's focus), and the image nudges. "n / N" is for the eyes (`aria-hidden`); a `role="status"` line, also the dialog's `aria-describedby`, reads "第 n 張，共 N 張：alt" (`image_position*`). The dialog itself takes the focus on open. On close, the thumbnail of the image shown is scrolled into view (instantly, behind the backdrop), the image zooms back into it, and it gets the focus. The dialog is `touch-action: pinch-zoom` (sideways drags are the swipe, not Chrome's back gesture) except while pinch-zoomed in. The controls are white on translucent black with the light teal ring in both themes (the backdrop is dark in both), 20px from the edges: `html:has(dialog.lightbox[open])` keeps a scrollbar gutter where clicks don't reach the dialog.
- The header is sticky and hides while scrolling down / reappears on scroll up (`static/js/nav-hide.js`, `.nav-hidden`). It stays visible while search is open or keyboard focus (`:focus-visible`) is inside it (Tab/Shift+Tab into the hidden bar brings it back), and hides on in-page `#` jumps so it never covers the target heading. Its spacing is padding with a negative bottom margin to keep the page start where the old collapsing margins put it.
- Skip link: the first element in `<body>` (`baseof.html`) is `<a class="skip-link" href="#main">` (i18n `skip_to_content`), off-screen until keyboard focus, then fixed top-left above the header (`.skip-link` at the end of `main.css`/`dark.css`). Every page template's `<main>` needs `id="main"`.
- Animations (lightbox zoom from the thumbnail, its slide between images and nudge at the ends, backdrop fade, search dropdown, cross-page View Transitions with a fixed header, the theme switch's crossfade) all live behind `prefers-reduced-motion: no-preference` in `main.css` / a `reduceMotion` check in `lightbox.js`. Headless Chrome with `--virtual-time-budget` does not advance animation timelines, so test animations in real time. The header and progress bar have their own `view-transition-name` (they stay put across page loads); for the theme switch, `baseof.html` puts `.theme-switching` on `<html>` for the length of the transition, which drops those names and the header's own background-color transition, so the whole page fades at one speed (the header used to lag behind the page).
- Images are centred: `figure` is a shrink-to-fit centred table (caption is a bottom `table-caption`, left-aligned to the image so the "↳" hangs off its corner; as wide as the text column; don't give figure side padding, a table caption would span it) and untitled standalone Markdown images get `<p class="image-block">` from the render hook. Those imgs are `display:block` + auto margins + `box-sizing: border-box` (the theme's 3px img border otherwise overflows `max-width:100%` by 6px and pushes the image off-centre).
- `static/eth-cg24/` is a standalone hand-built report and is not processed.
- A standalone Markdown image with a title (`![alt](/image/x.webp "caption")`, which is what the CMS writes) renders as a `<figure>` with a caption like the `figure` shortcode. This relies on `wrapStandAloneImageWithinParagraph = false` in `config.toml`; the render hook re-adds `<p>` for untitled images.
- The theme links CSS via `.Site.BaseURL` (absolute), so a static build served locally loads production CSS; build with `--baseURL http://localhost:PORT/` to test CSS changes. `hugo server` is unaffected.

## CMS (Sveltia)

- `static/admin/` serves Sveltia CMS at `/admin/` (script pinned in `index.html`; config in `config.yml`). Locally: `hugo server`, open `http://localhost:1313/admin/` in a Chromium browser → "Work with Local Repository" (writes files only, no git). Online: "Sign In with GitHub" (or a repo-scoped GitHub token); saving commits to `main` and deploys.
- "Sign In with GitHub" uses the Sveltia CMS Authenticator worker on Cloudflare: `sveltia-cms-auth` → `https://sveltia-cms-auth.jayin920805.workers.dev` (`backend.base_url`). Code is upstream `github.com/sveltia/sveltia-cms-auth` (not forked); redeploy with `git clone` + `npx wrangler@4 deploy` — secrets persist. Worker secrets: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `ALLOWED_DOMAINS=blog.jayinnn.dev`. GitHub OAuth App "Jayinnn Blog CMS", callback `<worker>/callback`, expiring user tokens (re-sign-in after ~8 h; the worker has no refresh flow). `backend.auth_scope: public_repo` keeps tokens off private repos — keep it unless the repo becomes private.
- `static/admin/editor-components.js` registers CMS editor components for the shortcodes `gallery`, `compare`, `linkcard`, `figure`, `callout`, `cite`, `footnote` (theme), `youtube`, `x`, `qr`, `details`, `highlight`, and for `> [!NOTE]` alerts (a block component, so the editor keeps them as written instead of escaping the `[`), so they show as editable blocks with previews and can be inserted from the editor. Patterns must parse existing posts exactly and write untouched shortcodes back byte-for-byte (figure keeps the original text in a hidden `raw` field). Test with `node` — the file exports the list when `module` exists.
- Bodies open as plain Markdown (`field_defaults.richtext.modes: [raw, rich_text]`). Typing in the rich-text editor re-serialises the whole body, and that corrupts existing posts. Rechecked in 0.246.1: `\\` → `\` in display math, `\<` → `<` (documented as intended), `_` → `\_` inside `$…$` (new), "``` python" → "```plain" plus a stray "python" line, list continuations re-indented into code blocks; only `\\` inside code fences is kept now. Keep raw first until all of these are fixed (test: `[rich_text, raw]`, type one character at the top of proof-of-second-derivative-test, 108-wuling-math-mid-term-test, from-hexo-to-hugo and P-vs-NP, save, diff). The toolbar and Insert menu work in raw mode, but Insert pastes the bare shortcode and Image a bare `![]()` at the cursor (upload under Assets, or in rich text); the component forms appear only after switching to rich text (switch at the right of the toolbar, per entry, not remembered). `[rich_text, raw]` or deleting the block makes rich text the default again.
- Preview: `index.html` registers the site's `fonts.css`/`main.css` (+ `dark.css` for dark mode) with `CMS.registerPreviewStyle`, and a preview template for posts/diaries (`CMS.registerPreviewTemplate`, built with `CMS.React.createElement`) that mirrors `single.html`'s title/meta/`.body`/tags markup — the default preview prints field labels as `<h4>`, which the theme shows as "#### Label". `editor-components.js` is loaded with a manual `?v=N`: bump it when editing that file.
- The CMS's own UI is themed in `index.html` via Sveltia's CSS variables (`--sui-base-hue: 174` = the site's #00796B teal, which Sveltia derives its accent/greys from; `--sui-font-family-*`). Its styles are injected later on `:root`, hence the `:root:root` selector. Variable names are from the pinned version — recheck when upgrading.
- Uploads go to `content/image` as WebP (max 2560px), referenced as `/image/...`. Posts use i18n `multiple_files` with the default locale omitted, matching `post.md` / `post.en.md`; new entries start zh-tw only and default to `draft: true` and `date` = now (`default: "{{now}}"`). Slug date tags use the local date (`slug.timezone: local`), so a diary's `YYYY-MM-DD.md` matches its date like `write-diary.py` (UTC gave yesterday's name before 08:00 in Taiwan).
- New posts need a typed English slug (`slug: {editable: [create], hint, pattern}`): the Slug panel in the editor sidebar opens by itself and saving waits until it matches `^[a-z0-9]+(-[a-z0-9]+)*$`. It becomes `content/posts/<slug>.md` (+ `<slug>.en.md`); existing posts can't be renamed from the CMS. A slug from the (Chinese) title gave files like `交大資工修課心得：測試-王小明.md`.
- "View on Live Site" (editor header; per-locale in the ⋮ content options) comes from `preview_path: "/{{locale}}/posts/{{slug | lower}}/"` + `i18n.omit_default_locale_from_preview_path` → `/posts/gsat-apply/`, `/en/posts/eth/` (Hugo lowercases paths). Drafts 404 there. If slugs ever become editable on update, `preview_path` also makes Sveltia write the old path into `aliases`.
- Post fields, in output order: Title, Date, Last updated (`lastmod`), Description, Keywords, Tags, TL;DR, Math (KaTeX), Table of contents (`outline`), Draft, Body, with hints (Tags lists the common tags). The "Math (KaTeX)" switch sets `katex: true`, which the theme needs to load KaTeX. Saving a post that had no `katex` key writes `katex: false`. Configured booleans are filled with their `default` (or false) when a file lacks the key and are always written, so don't add `toc`/`comments` (false hides them). Empty optional fields aren't written (`output.omit_empty_optional_fields: true`): no `description: ''`, `tags: []` or empty dates in new posts, and saving a post whose Description is empty drops its `description: ""` line (`index.html`, the meta description and search treat missing and empty alike). Only null/''/[]/{} count as empty, not false. Keys the config doesn't list are kept.
- The same goes for `draft` (default `true`): a post without a `draft:` key opens as Draft and saving it writes `draft: true`, which unpublishes it, so every post needs an explicit `draft:`. Since 0.246.1 opening a post no longer marks it as changed, and a `date` you don't touch is written back as it was (`01:20:13+07:00`, `16:58:15.000+08:00`, `2019-08-20`). Editing the Date input still drops the seconds and converts to the browser's offset (`01:20:13+07:00` → `02:25:00+08:00`): its datetime-local input has minute precision.
- Pages → About edits `about.md`/`about.en.md` (`file: /content/about.{{locale}}.md`, `format: toml-frontmatter`, so `+++` TOML stays TOML). `date` is a date-only datetime field because an unlisted TOML date comes back as a quoted string. Unlisted keys (`aliases`) are kept, moved after the listed ones. The first save adds `draft = false` to `about.md`. Its preview template is registered under the file name (`about`); saving one language rewrites both files.
- Post list: newest first (`sortable_fields.default`), Filter → Drafts / Published (ticked filters combine, so tick one), Group → Year; drafts end in "· DRAFT" (`summary` with `ternary`). "Published" is `draft ne: true`, so posts with no `draft` key count as published, as in Hugo.
- Version: Sveltia 0.246.1, pinned in `index.html` (it gets write access to the repo). Upgrade check: validate `config.yml` against the JSON schema embedded in the new bundle (`$ref: #/definitions/CmsConfig`); every post, diary and About must open with Save disabled; a title-only save may change only the known rewrites (quotes dropped, `[a, b]` → block lists, keys in config order with unlisted keys after them alphabetically, `katex: false` added, a final newline, one blank line after the front matter, `draft = false` in about.md, TOML arrays as `[ "about-me" ]`); recheck the rich-text cases above, the `--sui-*` names, the preview templates and every editor component (rich text: open an entry using each, then Insert each). Since 0.236 Settings → Developer can make "Work with Local Repository" commit on every save; it's off by default, so local saves stay uncommitted files. 0.238.1 fixed an XSS in the rich-text preview (only with `sanitize_preview: false`, not set here).
- Uploaded file names are slugified (`media_libraries.all.slugify_filename` + the global `slug` options `encoding: ascii`, `clean_accents: true`): "Screenshot 2026-10-17 at 15.22.25.png" → `screenshot-2026-10-17-at-15-22-25.webp`, "蘇黎世 Zürich Café.png" → `zuerich-cafe.webp`, and an all-Chinese name ("截圖 測試.png") gets a random `e8972cfc5cef.webp` (rename it under Assets if it matters). Before, names kept spaces and Chinese and the Markdown got `/image/Screenshot%202026….webp`, which `resources.Get` can't find, so `responsive-image.html` fell back to a plain `<img>` (no srcset, no lightbox). Applies to the Asset Library and to image fields (renamed on save). Identical content is deduplicated: uploading a copy of an existing image reuses that file.
- The optional post fields write nothing when left empty, so old posts only gain them when edited. `lastmod` ("Last updated") is a datetime in the same format as `date` with no default (so opening or saving never stamps it); its Now button writes the minute (`2026-10-17T16:37:00+08:00`), and `single.html` shows "· 更新於" only when it's later than the date. `keywords` is a plain string, as in all 16 posts that have it ("a, b, c", a trailing comma kept). `tldr` is a text field; the box shows only when it's non-empty. `outline` is a select, Automatic (null, left out of the file by `omit_empty_optional_fields`) or Always show (`outline: true`): a boolean field would write `outline: false` into every post it saves. The preview template mirrors `single.html` for these too (`.updated` in the meta line, the `.tldr` box).

## Footnotes & citations

- Footnotes are plain Markdown (`text[^1]` … `[^1]: note`), rendered by Goldmark; styled in `main.css`/`dark.css` (`.footnotes`, `.footnote-ref`).
- Or written in place: `text{{< footnote >}}note, **Markdown**/cite ok{{< /footnote >}}` (`shortcodes/footnote.html`; this is what the CMS "Footnote" insert writes, on one line). Prefer this over `[^1]`. Same markup as Goldmark's footnotes but ids `fn-N`/`fnref-N` (Goldmark's are `fn:N`/`fnref:N`), numbered by appearance via `.Page.Store`, listed by `partials/footnotes.html` before the references. The two kinds are numbered separately, so the partial logs a `WARN` when a post uses both. The list is only in `single.html`, so footnote text doesn't appear in RSS/`.Summary` (references behave the same).
- Citations: `{{< cite "key" >}}`, `{{< cite "k1, k2" >}}`, `{{< cite "key" "p. 12" >}}` → `[1]`, `[1, 2]`, `[1, p. 12]` (`shortcodes/cite.html`). Numbered by first use via `.Page.Store` (reset on every rebuild, so `hugo server` renumbers correctly); `partials/references.html` prints the list at the end of `.body` in `single.html`, after the footnotes. Unknown keys log a `WARN` and render `[?key]` — they don't fail the build.
- Sources: `data/references.yaml` (shared; keys lowercased) merged with a post's own `references:` frontmatter, which wins (`partials/reference-db.html`). Fields: `author` (string or list; >5 → first 3 + "et al."), `title`, `venue`, `year`, `url` or `doi`, `note`; or `text` (Markdown) for a hand-written entry. Add BibTeX with `python3 tools/bib2yaml.py refs.bib` (stdlib only; appends, skips existing keys unless `--force`).
- `static/js/notes.js` shows the footnote/reference in a hover popover (hover-capable devices only); loaded only on pages with footnotes or citations.
- `[markup.goldmark.renderer] unsafe = true` keeps raw HTML in Markdown, so HTML-emitting shortcodes (cite, figure) also work inside another shortcode's Markdown body (`details`). Side effect: HTML comments in posts reach the RSS feeds (`--minify` strips them from the HTML pages).

## Page templates

- Every page template has its own `<main id="main">` (index, list, term, terms, single, search, 404). `#main` is the skip-link target, so don't wrap the `main` block in baseof.html in another `<main>`.
- Dates are `<time datetime="YYYY-MM-DD">` (home list, archive/tag lists, post meta). The global `time { color: var(--muted) }` is for the home list; `.meta time` inherits, so the post's "發佈於 …" line and the archive keep one colour.
- One `<h1>` per page. On the home page it's the site title, hidden with `.visually-hidden` (screen-reader-only utility in main.css), and the post titles are `<h2 class="title">`; `.list-item h2.title` keeps the old h1 size, spacing and "# " marker.
- Home list text under each title: the post's `description`; when that is empty (`description: ""`, as the archetype and CMS leave it) or missing, the first 80 characters of `.Summary` as plain text, with headings, figures/captions and footnote marks removed (`index.html`).
- Posts end with newer/older links (`partials/post-nav.html`, between the tags and the comments): "← 較新的文章" left, "較舊的文章 →" right, the same directions as the pagination. Collection: `mainSections` minus `hidden: true`, `.ByDate.Reverse`, which orders same-date posts like the archive's `GroupByDate` (the home page's default sort orders those by title instead). Careful: `Pages.Next` returns the *newer* post.
- `404.html`: localized message, a search box (a plain GET form to `search/?q=`, which search.js reads, so it works without JS) and the 5 latest posts. GitHub Pages serves only the root (zh) 404.html, for every missing URL at any depth, so its links must stay root-relative.
- Search page (`_default/search.html`): every string is i18n (`search_*` keys). The messages search.js prints come from attributes on `[data-search-root]`: `data-text-start`, `data-text-no-results`, `data-text-result` / `data-text-results` (placeholders `{n}` count, `{q}` query) and `data-text-error`. The index's `displayDate` (search page and nav dropdown) uses the site's `date_format`.
- Tags: the tags page prints `.Page.LinkTitle` (the tag as written, "NYCU"), not `.Name` (the lowercased key, "nycu"). Tag links end in `/` (`/tags/<tag | urlize>/`); without it GitHub Pages answers with a redirect first.
- Nav (`partials/head.html`): the menu link of the page being shown gets `aria-current="page"` (URLs compared without the trailing slash; not styled). The language switch and the post's "Read in English" link carry `hreflang`/`lang` of the target language.

## SEO & feeds

- Meta description: `partials/meta-description.html` — the page's `description`, the home page's `params.description`, or for a post the first 160 characters of its summary; list pages without one get no tag. Keywords come from front matter `keywords` (an "a, b, c" string, as written).
- Open Graph/Twitter tags are `partials/social-meta.html` (not Hugo's internal templates). The image (`partials/page-image.html`) is the post's first local `/image/...` picture, converted to a JPEG ≤1200px wide; `summary_large_image` only when it's ≥600px wide. Otherwise, and on list pages, it's the 512px site icon (`params.og_image` overrides that default).
- JSON-LD (`partials/json-ld.html`): `BlogPosting` on posts, `WebSite` on the home page; author from `[params.author]`, with the http(s) `[[params.social]]` links as `sameAs`. Output through `jsonify | safeJS`; check changes with `json.loads` on the built pages.
- RSS: `layouts/rss.xml` overrides Hugo's embedded template (v0.167.0) only so the home feed lists posts (mainSections, not `hidden`) instead of every regular page (About, Search). Items carry `.Summary`, not full content (the footnote/reference lists only exist in `single.html`). Every page links a feed for autodiscovery: list pages their own, other pages the site feed.
- `robots.txt` (`enableRobotsTXT`, `layouts/robots.txt`) allows everything and names the sitemap. Don't `Disallow` noindex pages (English shells, `/admin/`): crawlers would never see the noindex. `layouts/sitemapindex.xml` leaves out a language whose sitemap would be empty (English today).
- Last-modified dates: `enableGitInfo` + `[frontmatter] lastmod = ["lastmod", ":git", "date"]` (CI checks out with `fetch-depth: 0`; a shallow clone would date every page by the latest commit). `partials/lastmod.html` (never earlier than the publish date) feeds the sitemap, JSON-LD `dateModified` and `article:modified_time`. A post shows "· 更新於 <date>" (i18n `updated_on`) only for a `lastmod` written in its front matter that's after its date: the last commit is often a bulk edit ("add keywords to all posts", tag merges). Hugo fills `.Params.lastmod` either way, so `single.html` treats a `.Lastmod` equal to `.GitInfo.AuthorDate` as git-derived. To label every post from git instead, drop `$explicitLastmod` from that condition.
- Menu URLs (and other internal links) end in `/`: GitHub Pages answers `/posts` with a 301 to `/posts/`.
- `theme-color` (browser toolbar) is a light/dark pair of metas in `header.html` matching the page background (`#ffffff`, dark.css `#202124`; keep in sync if those change). A saved manual theme overrides both at page load (dark-css script in `header.html`), and the theme button's `apply()` in `baseof.html` updates them the same way, or for "follow the system" gives each one back its own media query's colour so the browser follows the OS again (see Dark mode).

## Alerts & authoring shortcodes

- Alerts are plain Markdown (GitHub/Obsidian syntax): `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` (any case) on a quote's first line, the text on the following `>` lines. Text after the marker replaces the default title (`> [!WARNING] 千萬不要搭到 Zollikon`); `[!TIP]-` makes a collapsed `<details>`, `[!TIP]+` an open one. Obsidian's other types (`info`, `danger`, …) take the nearest of the five styles and are titled with the type. Rendered by `_markup/render-blockquote.html` (default titles `alert_*` in `i18n/`), styled by `.alert*` in `main.css`/`dark.css`. Every other blockquote goes through the same hook and must stay byte-identical to Goldmark's output (`<blockquote>\n…</blockquote>\n`). Prefer alerts over the old `callout` shortcode, whose text is a parameter.
- Galleries: `{{< gallery caption="optional" >}}`, one image per line — Markdown images `![alt](/image/a.jpg "caption")` (what the CMS Gallery component writes) or `{{< figure >}}` shortcodes — then `{{< /gallery >}}` (`shortcodes/gallery.html`). Justified rows: each item's flex-grow and flex-basis follow its aspect ratio (`--ar`, taken from the `width`/`height` that `responsive-image.html` emits, i.e. after AutoOrient), so the images in a row share one height uncropped; growth stops at 2× `--row` (200px, 120px on phones) so a lone image on the last row stays moderate. Images keep the WebP srcset (with a half-column `sizes`) and the lightbox. `.body .gallery img` resets `min-width` to 0: the lazy-load placeholder `min-width` of `figure img[width]` is for a full-column figure and pushed gallery images out of their cells. Warns about non-image lines, a missing `/image/` file or an empty gallery. External images have no known size: shown 3:2, cropped.
- Before/after slider: `{{< compare before="/image/nori.webp" after="/image/mitsuba.webp" before-label="Nori" after-label="Mitsuba" caption="…" start="50" >}}` (`shortcodes/compare.html`). Both images stacked in one figure (usual figure layout, max 500px tall); the after image is clipped from the left at `--pos`. `static/js/compare.js` (loaded by `single.html` only when the content has `<figure class="compare"`) moves the divider on click/drag (touch: horizontal drags only, `touch-action: pan-y` keeps vertical scrolling) and via the invisible range input (arrow keys, screen readers). Labels default to `compare_before`/`compare_after` in i18n; an empty label hides it. These images have no `data-zoom-src`, so the lightbox leaves them alone. Plain URLs work too (e.g. the `/eth-cg24/` report images). Warns about missing params, a missing `/image/` file or aspect ratios more than 2% apart. Without JS the divider stays at `start`.
- Link cards: `{{< linkcard "nycu-cs-eth-exchange" >}}` (a post's file name, or a path like `posts/eth`) shows the post's title, description (else its `tldr`) and date; `{{< linkcard page="eth" title="…" description="…" >}}` overrides them; `{{< linkcard url="/eth-cg24/project/" title="…" description="…" >}}` links anything else (title required; external hosts are shown). On a line of its own (`shortcodes/linkcard.html`). A bare name is tried under `mainSections` first (`/posts/eth`), because `site.GetPage "eth"` alone is ambiguous with the ETH tag page and fails the build; lookups go through `try`, so a bad reference is a `WARN` and the card is left out. It looks in the current language first, then the other: an English post linking a zh-only post gets the zh page, labelled 中文. Only front matter is read (no `.Summary`/`.ReadingTime`), so two posts carding each other can't recurse. The title link's `::after` covers the card, so the whole card is clickable.

## Deployment
- Theme CSS/JS are linked through `partials/asset-url.html`, which appends `?v=<md5 of the file>[:8]`. They're served with a 4-hour max-age under fixed names, so link any new static CSS/JS the same way or browsers keep stale copies after a deploy.

- Push to `main` triggers `.github/workflows/hugo.yml`, which builds with Hugo 0.167.0 extended and force-pushes to the `gh-pages` branch.
- `public/` and `resources/` are gitignored and never committed.

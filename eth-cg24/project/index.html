## Anisotropic Phase Function - Henyey-Greenstein (5 points) ### Source - `include/nori/phase_function.h` - `src/phase_isotropic.cpp` - `src/phase_hg.cpp` - `src/warptest.cpp` - `src/chi2test_phase.cpp` ### Implementation I create a new phase function `HenyeyGreenstein` which is inherited from `PhaseFunction` class. The implementation is mainly referenced from [PBRT book](https://pbr-book.org/3ed-2018/Light_Transport_II_Volume_Rendering/Sampling_Volume_Scattering#SamplingPhaseFunctions) and [Production Volume Rendering](https://graphics.pixar.com/library/ProductionVolumeRendering/). I will first discuss about the interface of the phase function, and then the implementation of the Henyey-Greenstein phase function. #### `PhaseFunction` Interface This class is inherited from `NoriObject` class. It has the following pure virtual functions, - `virtual Color3f sample(PhaseFunctionQueryRecord &pRec, const Point2f &sample)`: Sample the phase function and return the importance weight (i.e. the value of the phase function divided by the probability density of the sample with respect to solid angles). - `virtual Color3f eval(const PhaseFunctionQueryRecord &pRec)`: Evaluate the phase function for a pair of directions and measure specified in `pRec`. - `virtual float pdf(const PhaseFunctionQueryRecord &pRec)`: Compute the probability of sampling `pRec.wo` (conditioned on `pRec.wi`). - `virtual EClassType getClassType() const override { return EPhaseFunction; }`: Return the type of object. This interface will share by both isotropic and anisotropic phase functions. #### `PhaseFunctionQueryRecord` This struct is used to query the phase function, similar to the `BSDFQueryRecord` for BSDF. It contains the incident and outgoing direction and the measure. Noted that both the incident and outgoing direction are in the world coordinate system. #### `HG::HG` The constructor of this class will initialize the `g` parameter of the Henyey-Greenstein phase function. Also precompute some constants that will be used in the sampling and evaluation. If `g` is close to 0, I will set `m_isotropic` to true, and evaluate and sample the phase function as isotropic phase function. This will largely reduce the computation cost. Also if `g` is not valid (i.e. `g` > 1 or `g` < -1), it will throw an exception. #### `HG::sample` First we need to the measure to `ESolidAngle`. Then we need to sample the cosine of the scattering angle, which is defined as, $$ \cos \theta = -\frac{1}{2g}\left(1 + g^2 - \left(\frac{1-g^2}{1+g-2g\xi}\right)^2\right). $$ The above equation are from the PBRT book. We then compute the sine of the scattering angle. For the `phi` angle, we can just uniformly sample in $[0, 2\pi]$. Finally, we transform the scattering direction to the world coordinate system with the given incident direction. Noted that if `m_isotropic` is true, we will just uniformly sample on the sphere using `Warp::squareToUniformSphere`. The return value is just `Color3f(1.0f)`, becuase we already importance sample the phase function. #### `HG::pdf` First of all, if `m_isotropic` is true, it will return $\frac{1}{4 \pi}$. Otherwise, we will compute the probability of sampling the given outgoing direction, which is defined as, $$ f_P(\mathbf{x}, \theta) = \frac{1}{4\pi} \frac{1-g^2}{(1 + g^2 + 2g\cos \theta)^{3/2}}. $$ Noted that the above equation is difference from "Production Volume Rendering", due to the different direction of the outgoing direction. #### `HG::eval` The evaluation function will return `Color3f(pdf(pRec))`, because of the normalization of the phase function. ### Validation I modify `warptest` to make it able to visualize and run $\chi^2$ test for the phase function. I also create a new `chi2test_phase.cpp` which is modify from `chi2test.cpp` (for testing BSDF) to test the phase function. Addition to `HG` phase function, I also implement isotropic phase function in `src/isotropic.cpp`. Because the isotropic is essentially a special case of the Henyey-Greenstein phase function (when g=0), I will not discuss the implementation here. The result shows that the isotropic phase function is always pass the $\chi^2$ test. ## Extra Reconstruction Filters - Windowed Sinc (5 points) ### Source - `src/rfilter.cpp` ### Implementation To add new reconstruction filter, I create a new class `SincFilter` which is inherited from `ReconstructionFilter` class. The implementation is mainly referenced from [PBRT book](https://pbr-book.org/3ed-2018/Sampling_and_Reconstruction/Image_Reconstruction). #### `SincFilter::SincFilter` The `SincFilter` has two parameters, `tau` and `radius`. The `radius` is used to control the width of the sinc function, anything that is greater than `radius` will be set to zero. The `tau` is the parameter of the lanczos windowing function, where the lanczos function is defined as, $$ w(x) = \frac{\sin(\pi x / \tau)}{\pi x / \tau}. $$ #### `SincFilter::sinc` This function is used to evaluate the sinc function. The sinc function is defined as, $$ \text{sinc}(x) = \frac{\sin(\pi x)}{\pi x}. $$ In order to avoid divide by zero, we directly return 1 if $|x| < 10^{-5}$. #### `SincFilter::eval` This function first takes the absolute value of the input, then evaluate the sinc function. The result is multiplied by the lanczos windowing function, which is essentially `sinc(x / m_tau)`. ### Validation **Comparison between Mitsuba 3, Mine and Gaussian reconstruction filter** In the below comparison, we set both `radius` and `tau` as 3.0. I will specify which code is referenced in the following implementation. I will break the implementation into several parts, following the order of the source code. #### `Medium` Interface This class is inherited from `NoriObject` class. It has the following important functions, - `virtual Color3f transmittance_eval(const Point3f& t1, const Point3f& t2, Sampler *sampler)`: Return the transmittance between two points. - `virtual void sample_interaction(const Ray3f& ray, float sample, MediumInteraction& mei)`: sample the interaction point in the medium and store the result in `mei`. - `float sample_distance(float sample)`: sample the distance according to the maximum density of the medium. - `virtual Color3f getSigmaT(Point3f p)`: Return the extinct coefficient at a given point. - `virtual virtual Color3f getAlbedo(Point3f p)`: Return the single-scattering albedo at a given point. - `const Shape *getShape()`: Return the shape of the medium. - `const PhaseFunction *getPhaseFunction()`: Return the phase function of the medium. - `float getMajorant() const`: Return the majorant of the medium. - `void setShape(Shape *shape)`: Set the shape of the medium. - `void initTransform()`: Initialize the transformation of the medium, will be called after the bounding shape is fully loaded. (Used in heterogeneous medium) This interface has below member variables, - `PhaseFunction *m_phase`: The phase function of the medium. - `Shape *m_shape`: The shape that the medium is bounded by. - `float m_max_density`: The majorant of the medium. - `float scale`: a scale factor for the medium, which will scale the extinct coefficient and the majorant. #### `MediumInteraction` Struct This struct is ued to handle the interaction point in the medium. It contains the following fields, - `Point3f p`: The position of the interaction point. - `Vector3f wi`: The incoming direction of the interaction point. - `float t`: The distance from the ray origin to the interaction point. - `const Medium *medium`: The medium that the interaction point is in. - `Color3f sigma_t`: The extinct coefficient at the interaction point. - `Color3f sigma_s`: The scattering coefficient at the interaction point. - `float sigma_majorant`: The majorant of the medium. #### `Null` BSDF Because we need the shape to bounded the medium, but the shape should not effect the light in any scenario. Therefore, I create a `Null` BSDF which is inherited from `BSDF` class. The `Null` BSDF is essentially a delta BSDF, which will not effect any incoming light. When sample this BSDF, the outgoing light $w_o$ is set to $-w_i$. This BSDF should not effect any direct lighting, and only used to bound the medium. Therefore, when check direct illumination, we should ignore the `Null` BSDF. This change is apply to integrators, suck like `path_mis`, `path_vol_mis_single`, and `path_vol_mis_multiple`. #### `Shape` class A new member pointer `medium` is used to store the medium that the shape is bounded by. A new function `getMedium()` to get the medium that bounded by the shape. This function will return `nullptr` if the shape is not bounded by any medium. Another new function is `getTransform()`, which will get the transform of the shape. This function is useful for the heterogeneous medium, which I will discuss later. #### `Homogeneous` Medium The constructor is used to initialize the extinct coefficien, the albedo and the scale. This constructor will scale the extinct coefficient and the majorant by the scale factor. The `transmittance_eval` function will evaluate the transmittance between two points. The transmittance is defined as in Beer's law, which is $$ \text{Tr}(p_1, p_2) = \exp\left(\sigma_t \cdot |p_1 - p_2|\right). $$ The `sample_interaction` function will sample the interaction point in the medium. The interaction point is sampled by the transmittance sampling, using `sample_distance` function. This function won't check if the interaction point is out of the medium, instead, this will be handled by integrators. #### `path_vol_mis_single` Integrator In this part, I will only discuss the single scattering path tracer using ray marching technique. I will discuss about the equiangular sampling of single scattering in the next part. The single scattering will not consider any scatter events in the medium. Therefore, we won't use the `sample_interaction` function. Instead, we will detect whether the ray is in the medium, and evaluate the tranmittance between the ray origin and the intersection point. For calculating the contribution of the direct illumnination in the medium, I use ray marching technique to uniformly sample along the ray (with jittering). I also implement MIS, which is combined phase function sampling and emitter sampling. The number of samples in ray marching can be controlled by the `sps` parameter in the scene xml file. This integrator start Russian roulette after 3 bounces. #### `Cube` Shape This shape will creata a cube center at (0, 0, 0) with a side length of 2.0 ($[-1, 1]^3$). We can later use transformation to apply affine transformation to the cube. The cube will be later used to bound the heterogeneous medium and NanoVDB medium will be translate and scale to fit in the bounding cube. The `Cube` shape is inherited from `Mesh` class, following the same idea in [Mitsuba 3 (src/shapes/cube.cpp)](https://github.com/mitsuba-renderer/mitsuba3/blob/bc0d50171861b04fe06454ad92c07ba7449c2069/src/shapes/cube.cpp). By defining the cube as a mesh, we can easily apply transformation to the cube. The cube is defined by its vertices, normals, UV coordinates, and face indices. I integrate the code into the Nori framework. #### `Heterogeneous` Medium The `Heterogeneous` medium is used to simulate the cloud and the fog of the waterfall. The implementation is mainly referenced from [Production Volume Rendering](https://graphics.pixar.com/library/ProductionVolumeRendering/). The `Heterogeneous` medium is inherited from `Medium` class. Each `Heterogeneous` medium should be bounded by a cube, serve as the bounding box of the medium. I use NanoVDB to load the volume data. The volume data is a 3D scalar field, which is used to store the density of the medium. The volume data is loaded from a `.nvdb` file, which can be read by NanoVDB library. The volume data is then scaled and translated to fit in the bounding cube. The bounding cube is defined by the `Cube` shape. The properties of `Heterogeneous` medium are the following: - `filename`: path to the `.nvdb` file. - `albedo`: the single-scattering albedo of the medium. - `sigma_t`: the extinct coefficient of the medium. - `scale`: the scale factor of the medium. The constructor of the `Heterogeneous` will temporaily set the `m_max_density` to the maximum coefficient after scaling, which will be later multiply by the maximum value in the NanoVDB volume data. (in `loadGrid()` function). The `initTransform()` function will load the grid from the `.nvdb` file, get the bounding box and calculate the transformation matrix to that transform the volume data into $[-1, 1]^3$ cube. The final transformation matrix is then given by multiply the cube's transform and the volume data's transform (volume data -> $[-1, 1]^3$ cube -> cube's transform). We then calculate the inverse of this transformation matrix, which will be used to transform the world coordinate into the volume data's coordinate system. As for `transmittance_eval`, because we are dealing with heterogeneous medium, which we can't use Beer's law to evaluate the transmittance. Instead, we use ratio tracking technique to evaluate the transmittance. This part of code is mainly referenced from PBRT book and Production Volume Rendering. The `sample_interaction` function will sample the interaction point in the medium, same as the homogenous medium. We don't handle null-scattering in this function. The `getSigmaT` function will first transform the world coordinate into the volume data's coordinate system, then sample the extinct coefficient from the volume data. I use `nanovdb::math::createSampler<1>(acc)` to trilinear interpolate the density value. The extinct coefficient is then calculated by mulitply `m_sigma_t` and the density value. We only implement spatially constant albedo, so the `getAlbedo` function will return the albedo of the medium. The `getMajorant` function will return the majorant of the medium. The `loadGrid` function loads the volume data from the `.nvdb` file. The volume data is then scaled and translated to fit in the bounding cube. The bounding cube is defined by the `Cube` shape. The volume data is then stored in the `m_handle` member variable. This function also scaled the `m_max_density` by the maximum value in the volume data. **Difficulties:** 1. Directly save the `grid` instead of `handle` of NanoVDB grid will raise some error. I finally find that I should save the `handle` of the grid, and then use the `m_handle.grid()` to get the grid. 2. NanoVDB doesn't have a complete documentation or tutorial, it takes me some time to understand how to use the library. #### `path_vol_mis_multiple` Integrator This is an integrator that can handle participating media with multiple scattering event in the medium. The implementation is mainly referenced from [source code of Mitsuba 3 (src/integrators/volpath.cpp)](https://github.com/mitsuba-renderer/mitsuba3/blob/bc0d50171861b04fe06454ad92c07ba7449c2069/src/integrators/volpath.cpp). This integrator has two parameters: 1. `maximum_bounce`: The maximum depth of the path. 2. `minimum_bounce`: The minimum depth of the path. The integrator will start Russian roulette after `minimum_bounce` bounces. If the ray doesn't interact with the medium, it just acts like a normal path tracer with MIS (essentially `path_mis`). If the ray intersects with the medium, it will use the `sample_interaction` function to sample a free path, and use null scattering technique to decide this interaction point is a scattering event or not. If it is a scattering event, it will sample the phase function for the next ray direction and the emitter to calculate the contribution to radiance. If it is not a scattering event, it will continue to sample the free path along the same direcion. Noted that we don't need to explicitly calculate the tranmittance along the ray, because it will be canceld out. ### Validation #### **Homogeneous medium w/ single scattering** I evaluate the homogeneous medium with isotropic phase function and HG phase function with g=0.75 and g=-0.75. ## Equiangular Sampling of Single Scattering (10 points) ### Source - `src/path_vol_mis_single.cpp` ### Implementation This feature add a new parameter `equiangular` in `path_vol_mis_single`, if this parameter is set to true, then the integrator will use equiangular sampling instead of ray marching. The implementation is mainly referenced from the original paper: [Importance Sampling Techniques for Path Tracing in Participating Media](https://blogs.autodesk.com/media-and-entertainment/wp-content/uploads/sites/162/egsr2012_volume.pdf) and this [GitHub repo](https://github.com/sakanaman/equi-angular-sampling). I define a new function called `generate_equiangular` to generate sample point on the ray using equiangular sampling. Then using the sample point we can calculate the direct illumination from the light source. Noted that I first sample a point on the light source, then use that same point to perform equiangular sampling for `sps` times. ### Validation **Example scene as in the original paper** scene files: 1. `scenes/project/equiangular/no_equaiangular.xml` 2. `scenes/project/equiangular/equiangular.xml` This scene consist of a point light in the center, the three spheres is enclosed in a homogeneous medium. The first scene is rendered without equiangular sampling (using transmittance sampling), while the second scene is rendered with equiangular sampling.

As we can observe in the above comparisons, compared to ray marching, equiangular sampling can bring us less variance in the area that closed to light source. ## Environment Map Emitter (15 points; Extra feature) This is an extra feature that will create a very nice sky in our final rendering. This part I mainly reference the PBRT book, [this paper](https://web.cs.wpi.edu/~emmanuel/courses/cs563/S07/projects/envsample.pdf) and [this file](https://github.com/dehezhang2/Kombu/blob/main/code/src/emitters/envmap.cpp) ### Source - `src/envmap.cpp` - `include/nori/scene.h` - `src/path_mis.cpp` - `src/path_vol_mis_single.cpp` - `src/path_vol_mis_multiple.cpp` ### Implementation The `EnvMapLight` has the following properties: 1. `filename`: path to the HDRI file 2. `strength`: scale the illumnination 3. `phi_offset`: add offset to rotate the environment map along z-axis. I implement importance sampling by the illumnination of each pixel, which is done by first sampling the row based on row total illumination and then sample the column based on pixel illumination. The normalization of discrete PDF and CDF is done by using `nori/dpdf.h`. In the integrator, when the ray doesn't intersect with any object in the scene, it will use `scene->getEnvMapLight()` to get the environment map light. If the environment map light is not `nullptr`, it will evaluate the environment map light and calculate the contribution to the radiance. In emitter sampling, it also have chance to sample the environment map light, then sample the light position based on its illumination, the higher the illumination, the higher the probability to sample the light position. ### Validation I load the same HDRI into Mitsuba 3, getting the similar result. scene files: `scenes/project/envmap/cloudy_sky.xml`

深度閱讀

1. EgoX：人手、真機、模擬器一起預訓練，再用「embodiment dreaming」對齊表徵

arXiv:2611.16728｜cs.RO｜Carnegie Mellon University（Ding Zhao 組），合作者來自 NVIDIA、Bosch Center for AI、UC Berkeley 等

問題：要讓通用操作 policy 同時吃人類示範、真實機器人和模擬資料，最大的障礙是形態、感測和控制介面都不一樣。作者的立場是：轉移應該發生在「語意上對應的模態」之間，而感測和控制介面保留各自的實作，人、真機和模擬 agent 都視為平等的 embodiment。

方法：先把所有資料拆成具名模態：第一人稱主相機影像、各自的 proprioception、軀幹姿態、左右手腕姿態、左右末端關鍵點；動作則是同一組姿態模態的目標值，姿態放在共用的 egocentric 座標系，關節狀態留在各自的關節空間，缺的模態補 zero token，缺的動作不算 loss。架構 MXT+ 延續他們先前的 MXT：每個觀測模態有專屬 tokenizer（影像走跨 embodiment 共用的視覺 backbone，再接 embodiment 專屬的 cross-attention 聚合器），每個動作模態有專屬 action expert，中間是共用的 encoder-decoder Transformer 主幹，負責跨 embodiment 共享。新增的 embodiment dreaming 是只在訓練用的輔助目標：學生 tokenizer 用 8 個 learnable query 把影像、關節狀態聚合成 latent，然後預測未來數個時間點的 latent，目標由 EMA teacher 產生並 stop-gradient，loss 是 cosine 對齊加上可選的 smooth L1 幅度項。推論時 dreaming 相關模組全部丟掉，部署成本不變。預訓練每一步對每個 embodiment 各取一個 mini-batch 累積梯度，目標任務在目標機器人上的示範不進預訓練。

結果：六種 embodiment（Unitree G1 配 Inspire 五指手、xArm7 配 LEAP 手、模擬 G1、裝了夾爪的四足 LocoMan、Galaxea R1 Lite、拿固定鏟子的 Z1）、五個任務（抹醬、收工具、分類積木、T 形插入、鏟貓砂），共 13 組任務與機器人配對，baseline 是從頭訓練的 ACT 和微調過的 π0.5。跨 embodiment 預訓練讓 MXT+ 的平均 normalized task progress 從 0.63 升到 0.80，OOD 從 0.53 升到 0.77，13 組裡 12 組排第一。dreaming 本身（MXT+ 對 MXT）在七個設定把平均從 0.63 拉到 0.78。用 Gromov–Wasserstein 距離量手腕姿態 token 的跨機器人幾何，預訓練平均降 21.30%，dreaming 降 38.52%。另一個值得注意的消融：把所有相機和姿態合併成「粗」tokenizer 的版本，預訓練後在某些任務反而退步，Kitchen-Cleanup 直接掉到 0。

限制與疑問：資料全是自家團隊蒐集，規模有限；模擬只有一種人形和兩個廚房任務；加入新 embodiment 仍需人工指定模態對應和座標轉換；每個 embodiment 等量取樣，LocoMan 這種小資料集被重複使用，可能過擬合。逐任務的數字只在圖裡，表格不好直接比。

為什麼值得看：這是「模組化 tokenizer + 共用主幹」路線的一個乾淨實證，而且「預測未來 latent」這個 JEPA 式輔助 loss 對跨形態對齊的效果比預訓練本身還大。延伸想法：把 dreaming 的 target 換成 3D 場景表徵（例如 Gaussian 或點雲特徵），看能不能進一步拉近不同相機視角的機器人。

2. Learning the Task or Learning the Verifier？自我改進的機器人 agent 其實在學 benchmark 的判分程式

arXiv:2611.08318｜cs.RO｜北京大學、新加坡國立大學（通訊作者 Daquan Zhou）

問題：越來越多「自我改進」的 embodied agent 在為 VLA 設計的模擬 benchmark 上比較成績，但這些 benchmark 的成功條件常常比語言指令要求更多。作者問：讓 agent 讀得到成功條件（Criteria Exposure, CE），它寫出來的程式是更會做任務，還是更會迎合驗證器？

方法：一個凍結的 actor（GPT-6 Astra）寫 Python cell 呼叫機器人原語，另一個 learner（Claude Code + Opus 5.5）花五輪修改任務專屬的技能庫和記憶。w/ CE 時 learner 讀得到判分程式碼、分數和通過的階段；w/o CE 只看到每個 episode 成功與否，作者認為後者比較接近真實機器人。主要 benchmark 是 RoboDojo（雙臂 ARX-X5、只用 RGB），選 25 個任務，其中 16 個「條件超出指令」，9 個條件忠實於指令。作者另外改寫了那 16 個任務的判分程式（拿掉隱藏規則、修 bug、放寬門檻），稱為 CFaith，用來重新判同一批 episode。

結果：原始條件下，空技能庫 24.6%，w/o CE 47.8%，w/ CE 62.0%；但優勢只出現在 16 個條件超出指令的任務（27.8% 對 51.6%），忠實任務上兩者差不多（83.3% 對 80.6%）。換成 CFaith 重判，w/ CE 45.0%、w/o CE 47.2%，差距在雜訊內，優勢縮水 25.9 個百分點。更直接的證據：用 CFaith 學出來的庫在 CFaith 下 65.0%，拿去原始條件只剩 13.5%，每個庫都在「自己讀過的那套條件」下最好。轉移到新的 RoboDojo 任務時，w/o CE 反而比較好（80/200 對 71/200）。作者還發現 42 個任務裡約 33 個要求雙臂最後回到 home，而指令裡沒寫。

限制與疑問：CFaith 是作者自己寫的代理標準，尚未獨立審查；只比了全露和全不露兩個極端；每個任務 20 個測試 layout，蒸餾的變異沒估計；記憶內容「寫了什麼」的分析是讀文字推論，不是控制實驗。

為什麼值得看：如果你在做 LLM/VLM 寫程式控制機器人或自我改進迴圈，這篇是很實用的提醒：benchmark 分數的提升可能只是學會了判分器。實務上可以把「只用成功訊號」當預設，並在報告時附上換判分器後的分數。

3. G-STAR：把 tokenizer 壓到 32×、64×，靠「每格多放幾個 code」補回資訊

arXiv:2611.13004｜cs.CV｜北京大學、美團 LongCat 等（通訊作者 Xiaotong Li、Daquan Zhou）

問題：離散自迴歸（AR）圖像生成同時受困於量化損失和延遲：序列越長越慢，壓縮越狠每個 token 又得承載越多資訊。

方法：用乘積式多 codebook 量化，每個空間位置放 G 個 code。在名目位元預算 B = (HW/s²)·G·log₂K 固定下，空間壓縮倍率 s 乘上 α，G 就乘上 α²，AR 全域步數因此少 α² 倍，也就是「group 大小要隨壓縮倍率平方成長」。Tokenizer 的 encoder 從 Qwen-ViT 初始化、32× 下採樣，loss 包含重建、感知、對抗、與 Qwen-ViT 特徵的語意對齊、Gram 矩陣匹配和 commitment。再用無損的 2×2 重排把 32×、8 group 變成 64×、32 group。生成端的關鍵是 Semi-AR head：平行主幹一次算出所有 group slot 的表徵，再用一層帶 KV cache 的因果 Transformer 依序取樣，避免完全平行時 code 組合互相矛盾。模型有 Qwen3-8B 起始的 Pro（32×、G=16）和 Qwen3-1.7B 起始的 Flash（64×、G=32），解碼後另有一個 DiT refiner。

結果：GSTAR-Pro-8B 的 GenEval 0.84、DPG 83.38，Qwen-Image-Bench 50.07，略高於 Emu3.5（49.89）和 Qwen-Image（49.23），但 GenEval、DPG 落後 BitDance、Emu3.5、Qwen-Image（都在 0.86–0.87、88 左右），作者自己也只說「competitive」。Semi-AR head 在 512px 把 head 延遲從 6.44 秒降到 3.41 秒，GenEval 0.8253 對因果 head 的 0.8386。Flash 在單張 H200、1024×1024 的整體延遲從 22.23 秒一路優化到 2.50 秒（Semi-AR、CUDA graph、Triton、SGLang），共 8.9×。重建 PSNR：32× 的 f32g16 為 25.12 dB，高於 16× 的 Open-MAGVIT2（23.98）。

限制與疑問：摘要宣稱比先前離散 AR 快 20×，但正文量到的是對自家基線的 8.9×；ImageNet 消融中 G=32 的 gFID 惡化到 17.05，G=1 的 gFID 反而最好卻沒被討論；最後的 DiT refiner 有多少功勞也不清楚。沒有限制章節。

為什麼值得看：「把容量從空間軸搬到 channel/group 軸」的想法可以直接用在影片或 3D latent tokenizer 上，對 world model 這種序列極長的場景特別有吸引力。Semi-AR head 也是一個便宜的折衷，值得在 action tokenizer 上試試。
